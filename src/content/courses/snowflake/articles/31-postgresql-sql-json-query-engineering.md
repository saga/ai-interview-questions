# PostgreSQL SQL、JOIN、JSONB 与查询表达

## DML 与返回值

PostgreSQL 的 INSERT、UPDATE、DELETE 可以通过 RETURNING 返回被修改的行，避免额外查询。UPSERT 使用 INSERT ... ON CONFLICT，冲突目标必须与唯一约束或唯一索引匹配。

## JOIN 和结果粒度

写 SQL 前先说明每张输入表一行代表什么。事实表连接维度表时，要验证连接键是否唯一。一个订单连接多条订单明细后，订单头金额会重复出现；需要在正确粒度聚合或先聚合再 Join。

## JSON 与 JSONB

JSON 保留文本输入形式，JSONB 以二进制结构存储并支持索引和高效操作。JSONB 适合经常查询的半结构化字段，但不应把所有关系数据都塞入 JSONB。频繁参与过滤、连接和约束的字段通常应成为类型明确的列。

## Window 与 CTE

窗口函数可以在保留行的同时计算排名、累计值和分组统计。CTE 用于分阶段表达查询逻辑；现代 PostgreSQL 中，CTE 是否物化与版本、关键字和优化器规则有关，不能将每个 CTE 都视为临时物化表。

## PL/pgSQL 的位置

复杂业务计算优先评估 SQL 能否表达；需要事务控制、流程判断或数据库内过程封装时再用 PL/pgSQL。避免把简单查询包装成大量存储过程，增加调试和版本管理成本。

## 练习方向

用订单、客户、订单行和支付表练习：先定义粒度，再做聚合、窗口排名、JSONB 提取和 UPSERT。每个查询都核对行数、重复键和 NULL 行为。

2. JSONB 适合哪些访问模式，不适合哪些关系约束？
3. CTE 是否一定会物化？
