# 案例：资产管理平台的数据模型、研究检索与 Agent

## 场景

一家资产管理机构希望把投资组合、行情、基准、交易、基金估值、风险和研究资料放入统一分析平台。业务团队需要回答组合收益、持仓暴露、业绩归因和风险合规问题；研究团队还希望通过 Copilot 检索报告并生成分析草稿。

这不是一个“让 Agent 直接访问所有投资数据”的项目。首先要把数据实体、时间语义、业务口径和访问责任做好。

## 数据域

| 数据域 | 关键内容 | 主要质量风险 |
|---|---|---|
| Reference Data | Instrument、Currency、Issuer、Calendar | 标识映射和历史变更 |
| Portfolio | Position、Trade、Cash、NAV | 时点、重复交易和对账 |
| Market Data | Price、FX、Benchmark | 市场时区、缺失和修订 |
| Risk | Exposure、Factor、Stress | 模型版本和参数假设 |
| Research | 报告、公告、投资备忘录 | 来源、版本和访问限制 |

仓位、交易、估值和市场价格必须明确有效时间与记录时间。晚到的价格修订不能直接覆盖历史 NAV 计算而不留下证据。

## 数据建模

先定义每日持仓快照的粒度，例如“投资组合 × 工具 × 估值日期 × 币种”。再建立事实表和维度实体，统一 Instrument、Issuer、Portfolio、Benchmark 和 Currency 关系。NAV、收益和归因指标需要定义公式、基准、费用和汇率处理规则。

Research 文档保留来源 URI、发布日期、版本、权限范围和文本段落 ID。Cortex Search 检索时按用户可访问的投资组合、区域和文档分类过滤。

## 数据管道和对账

交易和持仓数据采用增量加载，行情与参考数据建立修订策略；每日完成 NAV、持仓数量、现金余额和基准权重对账。异常进入隔离队列，不允许 Agent 直接修正财务记录。

## Agent 应用边界

一个研究 Agent 可以组合结构化查询和非结构化检索：Analyst 查询组合指标，Search 查找研究证据，Custom Tool 计算受控的风险指标。输出必须区分数据库事实、模型计算和研究观点，引用数据时间和文档来源。

涉及交易下单、估值调整、限额变更或合规结论时，Agent 只能准备材料和建议，不能自行执行或批准。

## 验收

同一估值时点的持仓和 NAV 可重现；研究答案能够定位原文和版本；指标有明确 Owner 和 Golden Query；Role 与文档属性过滤经过越权测试；Agent 工具轨迹、计算输入和审批记录完整；失败时可追踪到数据批次、查询和来源。

## 检查题

1. 为什么投资组合指标必须明确时点和粒度？
2. 如何把研究资料检索权限传递到 Agent？
3. 哪些投资业务动作必须保留人工审批？
