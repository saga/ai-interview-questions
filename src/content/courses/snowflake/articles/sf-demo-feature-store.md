# Snowflake Feature Store 特征管理

## 本节要解决的问题

围绕实体、特征语义、时间有效性和复用治理特征，并控制训练/推理时点一致性。

Cortex Agents、ML 与 CoCo。明确目标、工具/模型边界、身份授权、输入输出、执行证据、评测和停止条件。

本教程只对应知识点 `sf-demo-feature-store`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 定义实体键、粒度、特征业务含义和时间窗口

业务指标必须定义分子、分母、过滤条件、时间口径、事实粒度和可加性。语义层能表达已确认的业务定义，却不能修复底层错误键、粒度或多对多关系。

### 防止预测时点之后的信息造成数据泄漏

机器学习流程要保存训练数据版本、特征定义、时间点、代码和模型版本，并使用独立验证集评估。避免未来信息泄漏；模型注册不等于业务效果已验收。

### 核验特征版本、刷新状态和训练/推理一致性

新鲜度目标不是固定运行周期或无条件 SLA。应结合刷新模式、依赖变化、资源消耗和实际刷新历史判断是否满足业务要求。

## 工程实施步骤

1. 将用户目标拆成可验证步骤，定义工具输入输出、身份、权限和停止条件。
2. 记录模型/工具版本、执行轨迹、失败状态、重试次数和业务幂等键。
3. 分别评估任务结果、工具选择、证据质量、越权拒绝、恢复能力和成本。

## 场景分析

用户要求 Agent 完成包含检索、分析和工具执行的任务。请定义工具选择、权限、执行轨迹、错误恢复和完成条件。

将场景转换为明确输入、状态变化和预期输出。逐项检查本节核心要求，区分配置事实、运行证据和待验证假设。缺少权限、版本、数据样本或官方行为证据时，明确记录未知项，不用猜测补齐。

## 常见误区

- **误区：** 把同名列视为同一业务特征
  **纠正：** 机器学习流程要保存训练数据版本、特征定义、时间点、代码和模型版本，并使用独立验证集评估。避免未来信息泄漏；模型注册不等于业务效果已验收。
- **误区：** 忽视实体重复和时间泄漏
  **纠正：** 机器学习流程要保存训练数据版本、特征定义、时间点、代码和模型版本，并使用独立验证集评估。避免未来信息泄漏；模型注册不等于业务效果已验收。
