# Cortex Agent 安全、MCP 与端到端评测

## 先确定 Agent 代表谁执行

Agent 可以访问 Analyst、Search、Custom Tool 或 MCP 服务。每个连接都要确定调用者身份、可访问对象、读写范围和审计主体。不要把 Agent 的服务身份自动扩大成账户管理员权限。

对外部 MCP 服务，还要评估服务端身份、传输保护、工具清单、输入验证、输出可信度、速率限制和数据离开 Snowflake 的路径。MCP 工具返回内容是数据，不是可信指令；外部结果不能改变系统授权和安全策略。

## 权限边界

只开放当前任务需要的工具；结构化查询通过受控语义层，而不是任意 SQL；检索服务执行权限过滤，不能依赖生成模型自行屏蔽；写操作和外部副作用设置明确授权和审批；Secret 使用受控对象管理，日志不记录明文凭据；访问和工具轨迹保留可审计证据。

## 评测不能只看回答

建立任务集覆盖成功路径、拒绝路径和异常路径。检查工具选择与参数是否正确；SQL 是否符合语义定义且结果正确；Search 证据是否支持回答；身份和权限是否正确传递；Prompt Injection 或恶意文档是否影响策略；工具失败、超时和重复执行是否安全；费用和延迟是否符合预算。

## 失败恢复

对只读查询可以有限重试；对写操作应使用幂等键并确认前一次是否完成。需要人工批准的动作应在批准前暂停，不能把模型自我确认当成用户授权。

## 上线门禁

先在隔离数据和受限 Role 下测试，再逐步扩大范围。记录 Agent 配置、工具版本、Prompt 版本、评测集、失败轨迹和授权审批。权限变化或工具更新后必须回归测试。

## 检查题

1. 为什么 Agent 服务身份不应该拥有账户级通用权限？
2. MCP Tool 的返回内容为什么不能作为策略指令？
3. 端到端 Agent 评测要覆盖哪些权限和失败路径？
