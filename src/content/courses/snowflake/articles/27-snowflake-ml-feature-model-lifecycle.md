# Snowflake ML：Feature Store、Model Registry 与模型生命周期

## 先确认问题是否需要机器学习

规则、SQL 聚合和统计分析可以解决的问题，不必为了使用 ML 增加模型运维成本。只有当预测、排序、分类或异常检测确实需要从数据中学习模式，并且有可用标签、评估方法和业务动作时，才应引入模型。

## Feature Engineering 的时间语义

Feature Store 管理特征定义和实体键。离线训练数据必须按预测时点还原当时可见的特征，避免把未来信息泄漏到训练样本。Point-in-time correctness 是防止数据泄漏的重要边界。

特征需要有 owner、更新频率、版本、类型和质量规则。训练与推理要复用同一特征语义，防止训练线上不一致。

## Model Registry

Registry 管理模型版本、元数据、评估信息和生命周期。部署前应记录训练数据版本、特征定义、代码版本、模型参数和评测结果。模型注册并不等于模型已经获得生产上线批准。

## 推理与监控

批量推理适合定期评分和大规模数据处理；在线推理更关注响应延迟、并发和可用性。需要监控输入漂移、输出分布、真实标签反馈和模型效果衰减。没有真实结果反馈时，不要把分布变化直接宣称为模型准确率下降。

## 评估与治理

根据业务损失选择指标。分类常见 Precision、Recall、F1、ROC-AUC；回归使用 MAE、RMSE 等；排序和推荐还要考虑分组和业务收益。高风险业务需要人工复核、可解释证据和降级策略。

## 检查题

1. Point-in-time correctness 为什么能避免特征泄漏？
2. Model Registry 中哪些信息需要随模型版本保存？
3. 输入数据漂移为什么不等于模型精度下降？
