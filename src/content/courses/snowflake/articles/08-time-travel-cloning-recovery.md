# Time Travel、零拷贝克隆与数据恢复

## 先区分三件事

Time Travel 允许在配置的保留窗口内查询、克隆或恢复历史数据；Zero-copy Clone 以共享底层数据文件的方式创建独立对象副本；Fail-safe 是 Snowflake 在特定条件下提供的灾难恢复服务窗口，不是用户可随时查询的历史版本，也不是日常备份替代品。

这三者不能被概括成“Snowflake 自动备份了所有东西”。保留期受账户 Edition、对象类型和参数配置影响，应以账户当前配置和官方文档为准。

## 查询历史版本

~~~sql
SELECT *
FROM ANALYTICS.MART.ORDERS
AT (TIMESTAMP => '2026-11-20 10:00:00'::TIMESTAMP_NTZ);

SELECT *
FROM ANALYTICS.MART.ORDERS
BEFORE (STATEMENT => '01b...query-id...');
~~~

AT 表示选取指定时间点，BEFORE 可以按语句边界查看变更前状态。用于事故分析时，先记录目标时间、Query ID、受影响对象和当前数据快照，避免用错误时间点覆盖现场。

## 零拷贝克隆

~~~sql
CREATE DATABASE INVESTIGATION_CLONE
CLONE PROD_ANALYTICS
AT (TIMESTAMP => '2026-11-20 10:00:00'::TIMESTAMP_NTZ);
~~~

Clone 创建后可独立修改对象定义和数据；初始文件可共享，后续变更才逐步形成额外存储消耗。它适合创建调查环境、测试环境和短期分支，不应被误解为可以无限期、零成本保存的备份。

## 恢复操作流程

1. 确认事故范围：对象、时间、影响下游、误操作语句。
2. 先克隆历史版本到隔离环境，验证行数、关键指标和业务键。
3. 对比当前与历史状态，评估只恢复受影响对象还是整库。
4. 在变更窗口内执行恢复，记录执行语句和回滚方案。
5. 对下游任务、缓存、语义视图和数据产品做一致性检查。

不要在尚未确认恢复目标时直接执行 OR REPLACE。恢复表数据也不等同于恢复由外部系统维护的文件、外部 Catalog 或独立应用状态。

## 设计保留策略

将保留期与 RPO、RTO、审计需求、法规要求、成本和数据生命周期关联。需要跨账户、跨区域或长期留存时，应设计独立的数据副本或归档方案，并验证恢复流程，而不是只依赖 Time Travel。
