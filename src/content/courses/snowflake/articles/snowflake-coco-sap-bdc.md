# SAP BDC Zero-Copy Connector 生命周期

## 本节要解决的问题

管理 SAP BDC 与 Snowflake 零拷贝连接器的前置条款、权限、连接状态、数据产品消费与发布流程。

企业数据架构与治理。先定义业务实体、事实粒度、指标口径和访问责任，再决定物理模型、语义定义与权限策略。

本教程只对应知识点 `snowflake-coco-sap-bdc`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 组织层面需要由 ORGADMIN 一次性接受相应条款，Snowflake 角色还需具有目标 Schema 的连接器权限。

权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。

### 消费 SAP 数据产品与向 SAP BDC 发布 Snowflake 数据产品是不同工作流，需要不同权限与验收。

权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。

### 连接器状态变化包含异步阶段，只有处于正确连接状态才能执行后续挂载或发布操作。

可重复交付需要把版本源、目标环境、执行身份、依赖顺序、密钥、部署计划、测试证据和回滚路径连在一起。代码合并或 SQL 执行成功都不等于上线验证完成。

### 断开连接前必须按生命周期约束处理共享发布状态与 Catalog-Linked Databases。

Iceberg 的数据文件、快照/Manifest 元数据和 Catalog 指针属于不同层次。要明确元数据提交权、文件与快照维护责任，以及多引擎一致性和权限。

## 常见误区

- **误区：** 认为接受条款、创建连接器和授予数据访问权限是同一步骤。
  **纠正：** 权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。
- **误区：** 把异步 CONNECTING 状态当作连接已经可用。
  **纠正：** 回到本知识点的输入条件、执行边界和验证证据，确认判断成立的前提，不要把简化经验当普遍规则。
- **误区：** 混淆消费 SAP 共享数据产品和反向发布 Snowflake 数据产品。
  **纠正：** 可重复交付需要把版本源、目标环境、执行身份、依赖顺序、密钥、部署计划、测试证据和回滚路径连在一起。代码合并或 SQL 执行成功都不等于上线验证完成。
- **误区：** 断开或删除连接器时忽略 Catalog-Linked Databases 与 share-back 状态。
  **纠正：** Iceberg 的数据文件、快照/Manifest 元数据和 Catalog 指针属于不同层次。要明确元数据提交权、文件与快照维护责任，以及多引擎一致性和权限。
