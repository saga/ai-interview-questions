# CoCo 辅助构建端到端数据与 AI 应用

## 本节要解决的问题

组合接入、转换、质量、结构化/非结构化检索和 Agent 交付形成可验证方案

Cortex Agents、ML 与 CoCo。明确目标、工具/模型边界、身份授权、输入输出、执行证据、评测和停止条件。

本教程只对应知识点 `snowflake-guide-coco`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 组合接入、转换、质量、结构化/非结构化检索和 Agent 交付形成可验证方案

检索系统要分别评估数据完整性、索引新鲜度、权限过滤、Recall@K/排序相关性和最终答案忠实度。命中一个文档不代表证据充分。

### 分层验证摄取、Dynamic Tables/dbt、数据质量、语义视图、检索工具和 Agent 评测

文件入口、文件解析和目标表写入必须分别验证。检查路径与文件清单、格式选项、列匹配、拒绝行、加载历史和目标行数；失败重跑前先确认之前是否已部分提交。

### 结构化/非结构化路径分别做质量门禁，并用 ground-truth 集评测 Agent

Agent 可靠性来自工具契约、调用身份、权限、停止条件、失败恢复和可审计轨迹。Thread 不是业务状态库；工具返回内容是待验证数据，不是系统指令。

## 工程实施步骤

1. 将用户目标拆成可验证步骤，定义工具输入输出、身份、权限和停止条件。
2. 记录模型/工具版本、执行轨迹、失败状态、重试次数和业务幂等键。
3. 分别评估任务结果、工具选择、证据质量、越权拒绝、恢复能力和成本。

## 场景分析

用户要求 Agent 完成包含检索、分析和工具执行的任务。请定义工具选择、权限、执行轨迹、错误恢复和完成条件。

将场景转换为明确输入、状态变化和预期输出。逐项检查本节核心要求，区分配置事实、运行证据和待验证假设。缺少权限、版本、数据样本或官方行为证据时，明确记录未知项，不用猜测补齐。

## 常见误区

- **误区：** 端到端运行成功就可以省略分层质量检查
  **纠正：** AI 生成内容必须按普通代码变更审查：检查对象、权限、过滤、Join 粒度、数据副作用和执行计划；使用固定样本验证结果等价，并保留 Diff、测试和回滚证据。
- **误区：** Agent 评测可替代 SQL 模型回归
  **纠正：** Agent 可靠性来自工具契约、调用身份、权限、停止条件、失败恢复和可审计轨迹。Thread 不是业务状态库；工具返回内容是待验证数据，不是系统指令。
- **误区：** 所有实时数据必须变成文档供 Search 使用
  **纠正：** 检索系统要分别评估数据完整性、索引新鲜度、权限过滤、Recall@K/排序相关性和最终答案忠实度。命中一个文档不代表证据充分。
- **误区：** Quickstart 不需要容量/成本测试
  **纠正：** AI 生成内容必须按普通代码变更审查：检查对象、权限、过滤、Join 粒度、数据副作用和执行计划；使用固定样本验证结果等价，并保留 Diff、测试和回滚证据。
