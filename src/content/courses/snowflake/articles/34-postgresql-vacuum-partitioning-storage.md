# PostgreSQL VACUUM、膨胀与分区表

## VACUUM 为什么必要

MVCC 保留旧 Tuple Version 以满足活动事务快照。死元组不再被需要后，VACUUM 才能标记空间可复用并维护可见性信息。Autovacuum 根据表统计和阈值自动触发清理与统计分析，但高更新率、大表、长事务和复制槽都可能让清理落后。

VACUUM 通常不把文件直接缩小到操作系统；它优先让表内部空间可复用。需要重写文件或回收文件系统空间时，应单独评估 VACUUM FULL、pg_repack 等方案的锁和空间需求。

## 膨胀与排查

检查 dead tuples、last_autovacuum、last_autoanalyze、长事务、复制槽和表更新频率。若 xmin 被长事务或复制槽阻塞，清理无法回收更早版本。不能只把 autovacuum 阈值调得更激进而忽视根因。

## 分区表

Range 分区适合时间或数值区间；List 分区按离散分类；Hash 分区用于分散数据。分区裁剪能够跳过不相关分区，但前提是查询条件与分区键匹配。

分区不是自动性能优化。过多小分区会增加规划和运维负担；全局唯一约束、跨分区索引和外键能力需要结合当前 PostgreSQL 版本核验。

## 生命周期治理

日志、事件和历史流水可以按时间分区，过期时通过 DETACH / DROP 分区控制生命周期，通常比逐行 DELETE 更可控。但删除分区前必须验证保留、归档、下游消费和审计要求。
