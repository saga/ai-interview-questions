# Agent 回答与来源核对基础

## 本节要解决的问题

判断 Agent 的回答是否真正由工具返回的数据或可追溯来源支持，而不是只看文字是否流畅。事实型回答需要来源证据，计算型回答需要查询结果和口径，建议型回答需要区分事实、推断和未经验证的行动方案。

## 核心知识

### 事实回答必须能回到原始证据

使用 Cortex Search 时，证据通常是文档片段及其属性；使用 Cortex Analyst 时，证据包括生成的 SQL、执行结果和 Semantic View 指标定义；使用 MCP/Custom Tool 时，证据是工具返回的结构化状态和外部业务系统中的记录。

最终回答应能说明每个关键结论来自哪个工具结果、哪个文档片段或哪个查询。只引用 Search 返回的标题、但片段内容并不支持结论，不算有效引用；只显示 Analyst SQL、没有核对执行结果，也不能证明答案正确。

### 计算结果要与指标定义和执行结果一致

对金额、数量、排名、比例和时间范围，必须核对查询中的过滤、Join、聚合和业务口径。Semantic View 的 Metric 可能定义了已付款收入，而用户问的是已下单收入；工具调用成功也可能使用了错误指标。

对于百分比和排名，检查分子/分母、分母为零、时区、缺失值和多对多 Join。对来自多个工具的数据，确认它们的时间窗口和粒度一致，再进行比较。

### 回答中应区分证据、推断和未知

Agent 可以结合多条证据形成解释，但需要把“原始数据明确显示”“模型推断”以及“现有资料无法判断”区分开。证据冲突时，应指出冲突来源并暂停结论，不能选择更符合用户预期的一方。

建议或操作计划不等于操作已经执行。外部写入工具的返回状态需要通过业务系统查询验证；对于审批、付款、账户变更等动作，应有确定性授权、幂等和明确确认流程。

## 工程实施步骤

1. 为回答的关键事实定义最低证据要求：来源 ID、文本片段/页码、Query ID、工具返回对象或外部业务记录 ID。
2. 对 Search 结果核对来源文档版本、段落内容、访问权限和有效日期。
3. 对 Analyst 结果保存生成 SQL、实际 Query ID、执行参数、返回数据和 Metric 定义。
4. 对外部工具结果保存 request_id、业务对象 ID、状态和响应时间，并在必要时回查权威系统。
5. 将答案生成分成 evidence、calculation、inference 和 recommendation 区域；不要把推断写成源数据事实。
6. 用规则检查引用是否指向实际检索片段，关键数值是否能从结果集复算，时间和单位是否一致。
7. 对缺少来源、结果为空、证据互相矛盾、过期文档或工具超时的情况，要求说明限制或拒答。
8. 对涉及外部副作用的操作，先由业务规则和权限验证，再使用幂等请求 ID 执行；执行后回查目标状态。
9. 建立独立的问答测试集，按引用准确率、事实支持率、数值一致性、拒答正确率和越权拒绝分别评估。
10. 把生产中发现的错误回答转成回归样本，重跑相同 Agent 和工具版本，确认修复没有带来新的错误。

## 场景分析

Agent 读取退款政策，查询订单系统后回答“该客户符合全额退款条件”。但 Search 结果引用的是旧政策版本，而 Analyst 结果只显示订单状态，没有包含退款金额和已退款金额。

回答虽然语言通顺，却缺少支持“全额退款”的关键证据。应用应核对政策生效日期、当前订单金额、历史退款总额和适用条款。若证据不全，应把结论降级为“可能符合，需核对已退款金额”，或拒绝给出确定判断。

验收使用政策版本变更、订单已部分退款、订单取消、重复退款和跨区域规则样本，检查引用与计算能否支持最终结论。

## 常见误区

- **只检查回答是否流畅。** 需要检查引用、工具结果、时间和业务口径。
- **引用了文档标题就认为有来源。** 引用片段必须实际支持对应结论。
- **工具调用成功就认为答案正确。** 仍需核对输入参数、业务定义和返回数据。
- **将模型推断标记为事实。** 证据、推断和未知应清楚区分。
- **把“建议创建工单”写成“工单已创建”。** 写操作需要工具执行证据和目标系统回查。
- **只使用整体正确率评测。** 引用、数字一致性、拒答、权限和动作状态需要独立指标。

## 完成标准

- [ ] 能区分 Search、Analyst 和外部工具的证据类型。
- [ ] 能核对引用片段是否真正支持结论。
- [ ] 能验证计算结果与指标口径一致。
- [ ] 能区分事实、推断、建议和未知。
- [ ] 能为高风险工具动作设计回查和幂等验证。

## 自测

1. Agent 引用的政策文档已过期，为什么不能直接使用该引用支持当前结论？
2. Analyst 查询执行成功，但指标过滤使用了错误的支付状态，应该在哪个阶段发现？
3. 如何验证“退款金额符合政策”而不只是“订单状态为已完成”？
4. Agent 表示“已创建工单”，但 MCP 返回的是 timeout，应该如何处理？
5. 为什么引用准确率和事实支持率需要分开评估？
