# Snowflake Git 集成、CLI 与环境晋级

## 本节要解决的问题

为 SQL、对象、语义定义和管道建立版本控制、可重复部署、分环境配置与最小权限。

Snowflake 工程交付与运维。重点是让配置、执行身份、变更、运行证据和恢复过程可重复、可审查、可追踪。

本教程只对应知识点 `snowflake-git-cli-cicd`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 将定义放入 Git 并在 PR 审查依赖与破坏性变化

可重复交付需要把版本源、目标环境、执行身份、依赖顺序、密钥、部署计划、测试证据和回滚路径连在一起。代码合并或 SQL 执行成功都不等于上线验证完成。

### 使用专用最小权限身份并隔离密钥/环境配置

权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。

### 建立开发、测试、生产晋级及上线后验证

可重复交付需要把版本源、目标环境、执行身份、依赖顺序、密钥、部署计划、测试证据和回滚路径连在一起。代码合并或 SQL 执行成功都不等于上线验证完成。

## 工程实施步骤

1. 明确 Git 版本、目标环境、部署身份、对象依赖和所需权限。
2. 先在低风险环境生成变更计划并运行静态、集成和数据验证。
3. 发布后核对对象定义、实际数据、运行指标和回滚点。

- **误区：** 生产手工改对象却不回写 Git
  **纠正：** 可重复交付需要把版本源、目标环境、执行身份、依赖顺序、密钥、部署计划、测试证据和回滚路径连在一起。代码合并或 SQL 执行成功都不等于上线验证完成。
