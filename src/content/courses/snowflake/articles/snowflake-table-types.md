# Permanent、Temporary、Transient 与 Iceberg 表

## 本节要解决的问题

根据数据保留和存储管理需求选择表类型.

Iceberg / Lakehouse。理解数据文件、表元数据、Catalog、写入协调、计算引擎和维护责任。

本教程只对应知识点 `snowflake-table-types`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 根据数据保留和存储管理需求选择表类型.

Iceberg 的数据文件、快照/Manifest 元数据和 Catalog 指针属于不同层次。要明确元数据提交权、文件与快照维护责任，以及多引擎一致性和权限。

### 按会话/生命周期、恢复要求和外部互操作需求选用对应表类型.

平台短期恢复能力、零拷贝克隆和长期业务历史保存解决不同问题。恢复前记录时间点、对象范围和影响面，在隔离副本验证后再执行生产恢复。

## 常见误区

- **误区：** Temporary 表适合永久保存多年审计数据
  **纠正：** Iceberg 的数据文件、快照/Manifest 元数据和 Catalog 指针属于不同层次。要明确元数据提交权、文件与快照维护责任，以及多引擎一致性和权限。
- **误区：** 所有表类型具有完全相同的 Fail-safe 和保留行为
  **纠正：** 平台短期恢复能力、零拷贝克隆和长期业务历史保存解决不同问题。恢复前记录时间点、对象范围和影响面，在隔离副本验证后再执行生产恢复。
- **误区：** Iceberg 只是另一种 Warehouse 类型
  **纠正：** Snowflake 的存储、计算与 Cloud Services 属于不同责任边界。分别检查数据持久化、Warehouse 资源以及平台级元数据、认证与协调，不能把一个层次的设置当作另一个层次的修复手段。
