# Snowflake CLI、Git 与 Notebook CI/CD

## 本节要解决的问题

让代码、配置、执行身份和环境晋级成为可重复审查的交付流程

Snowflake 工程交付与运维。重点是让配置、执行身份、变更、运行证据和恢复过程可重复、可审查、可追踪。

本教程只对应知识点 `snowflake-guide-cicd`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 让代码、配置、执行身份和环境晋级成为可重复审查的交付流程

可重复交付需要把版本源、目标环境、执行身份、依赖顺序、密钥、部署计划、测试证据和回滚路径连在一起。代码合并或 SQL 执行成功都不等于上线验证完成。

### 把源代码与环境参数纳入 Git，使用 CLI/CI 部署并验证数据和权限

权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。

### 使用受限服务身份、参数化环境配置和受保护发布门禁

可重复交付需要把版本源、目标环境、执行身份、依赖顺序、密钥、部署计划、测试证据和回滚路径连在一起。代码合并或 SQL 执行成功都不等于上线验证完成。

## 工程实施步骤

1. 明确 Git 版本、目标环境、部署身份、对象依赖和所需权限。
2. 先在低风险环境生成变更计划并运行静态、集成和数据验证。
3. 发布后核对对象定义、实际数据、运行指标和回滚点。
