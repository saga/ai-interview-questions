# 研究 Copilot、Cortex Search 与投资备忘录

## 本节要解决的问题

投资经理准备投资委员会材料，需要回答：“公司 A 最近两个季度的盈利预期为何下调？这是否改变我们对组合风险的判断？”

答案涉及三种不同材料：财报与持仓数据是结构化事实，分析师报告和会议纪要是研究证据，投资政策和风险限额是规范依据。将这些资料一起交给 LLM 并要求它总结，可能把预测当成已实现业绩、把旧版研究报告当成最新观点，或把某位分析师的意见说成公司的正式披露。

研究 Copilot 的关键不是“搜到几段相似文字”，而是让每个结论都能追溯到正确版本的来源，并把事实、观点和政策判断分开。

## 核心知识

### 研究文档需要稳定身份和版本，而不只是文件名

同一发行人可能有多份报告，文件名甚至会重复。建议在入库前为每份材料建立稳定的文档登记信息：

| 字段 | 作用 |
|---|---|
| document_id | 文档稳定标识，文件改名后仍可追踪 |
| issuer_id | 对应规范发行人身份，而不是只依靠公司简称 |
| document_type | 年报、业绩公告、研究报告、会议纪要、政策等 |
| author / publisher | 作者、券商、公司或监管机构 |
| published_at | 正式发布日期 |
| effective_from / effective_to | 政策或评级适用的生效区间 |
| version | 同一材料的修订版本 |
| language | 原文语言 |
| access_scope | 哪类用户或团队允许检索 |
| source_uri | 原始存储位置和可打开路径 |

发布日期和生效日期不能混为一谈。研究报告可能在 11 月 20 日发布，政策却在 12 月 1 日才生效；回答 11 月 27 日的历史问题时，不能引用尚未生效的政策。

对于修订报告，应保留版本关系，不要把新文件覆盖旧文件后丢失历史。搜索结果需能标出“当前有效版本”和“历史版本”，以便用户判断结论发生变化的时间。

### 文档解析和切分要保留标题、页码与上下文

财报、研究报告和会议纪要通常不是一段连续纯文本。表格、脚注、图表说明、章节标题和页码都可能承载关键含义。抽取文本时应保留：
- 章节标题和层级，避免把“风险因素”与“估值假设”混在同一块。
- 页码、表格标题和脚注引用，便于用户回到原始文件。
- 发行人、发布日期、文档类型和版本等检索属性。
- 原文语言与必要的规范化字段；翻译文本不能替代原始引用。

切分大小应根据材料类型决定。短公告可以按段落或章节切分；长篇研究报告可按章节、子章节和语义段落组合。过小的 Chunk 会丢失“该数值属于哪个期间、哪个表格”的上下文；过大的 Chunk 又会让检索结果混入无关段落。

对于重要财务数字，不要只依赖 PDF 文本抽取。还要核对表格结构、单位、币种、正负号和期间标签；同一个“Revenue”可能是季度收入、年初至今收入或全年预测。

### Cortex Search 提供证据候选，不能替代事实校验

研究 Copilot 可以用 Cortex Search 检索非结构化材料，例如分析师报告、年报、管理层问答和投资政策。每条检索结果至少要能回到文档 ID、版本、章节/页码和原始链接。

结构化指标应由受治理的 Semantic View 或明确的 SQL 计算。例如“本基金持有公司 A 的比例”必须读取某个估值日期的组合持仓和 NAV；研究报告里的“目标权重”不能替代实际持仓。

一个基本的证据工作流是：

~~~mermaid
flowchart TD
  A["投资问题"] --> B["解析发行人、指标、时间和组合范围"]
  B --> C["Semantic View / SQL 获取结构化事实"]
  B --> D["Cortex Search 检索报告与政策"]
  C --> E["检查业务日期、币种、数据版本"]
  D --> F["检查文档版本、发布日期、页码和适用范围"]
  E --> G["对齐发行人和时间"]
  F --> G
  G --> H["生成事实/观点/政策分层的回答"]
  H --> I["引用核查与人工复核"]
~~~

如果 Search 找到一份 2024 年的报告，而问题询问 2026 年最新评级，应将旧报告作为历史对比，而不是当作当前观点。没有找到有效文件，不等于“公司没有风险披露”；它可能意味着索引尚未刷新或搜索范围不完整。

### 权限必须在检索前落实，不能靠模型隐藏结果

研究报告可能包含受限的交易意图、未公开信息或特定客户材料。不能先把全部文档都检索出来，再让 LLM 判断哪些能展示。

应在数据接入和检索服务设计中定义访问范围：
- 将文档索引拆分到适当的服务或安全域，避免不必要的跨团队共享。
- 将访问范围、团队、发行人范围和材料等级作为可校验的元数据。
- 在可信服务端根据当前身份构造允许的检索范围；不要接受用户输入中的任意过滤条件来扩大范围。
- 确认调用者有权使用目标 Cortex Search Service，并对无权服务或无权文档做负向测试。
- 日志只记录必要的文档 ID、请求标识和访问结果，避免把受限正文复制到不必要的审计通道。

即使检索请求受限，答案也必须保留引用与来源版本。若同一文档对不同用户有不同授权，应明确由可信服务端执行授权，而不是让模型自行筛选。

### 研究观点与公司事实必须分开表述

同一公司可能同时有：
- 公司正式披露：已实现的收入、现金流、债务和风险事项。
- 分析师观点：盈利预测、目标价、评级和投资假设。
- 市场数据：价格、成交量和估值倍数。
- 内部判断：投资团队对风险和仓位的解释。
- 政策规则：集中度、国家、行业或流动性限额。

例如，报告写着“明年 EBITDA 预计下降 8%”，这是分析师预测，不是已实现的 EBITDA；另一份公司公告可能显示上一财年 EBITDA 增长 3%。回答必须保留各自的期间、单位和来源，不能将两个数字拼成一个“公司 EBITDA 下降”。

若要说明评级变化，应比较同一机构、同一发行人、可比报告类型的前后版本，并注明评级发布日。若机构更换了模型或评级尺度，也不能把数值差异直接解释成风险变化。

## 工程实施步骤

1. 先定义研究问题所需的事实、观点和政策证据，以及发行人、组合和时间范围。
2. 为报告、公告和政策建立稳定 document_id、issuer_id、类型、作者、发布日期、版本、生效期和访问范围。
3. 解析文件时保留标题、页码、表格和脚注；对重要财务数据抽样与原始文档核对单位、币种和期间。
4. 根据文档结构切分 Chunk，保留可追溯元数据；不要使用同一固定字符长度切分所有文件。
5. 将需要全文检索的文档接入 Cortex Search；结构化持仓、价格、NAV 和市场数据通过 Semantic View 或 SQL 获取。
6. 在可信服务端根据当前用户构造服务选择与过滤条件，执行权限正向和负向测试。
7. 检索结果返回后检查发布日期、版本、生效期、issuer_id、页码和来源链接。
8. 生成回答时分开标记公司披露、市场数据、分析师预测、内部观点和政策要求。
9. 对每个数字和关键判断执行引用覆盖检查；没有支持来源的句子要删除或标记为推断。
10. 建立代表性查询集，评估召回、版本新鲜度、权限过滤、引用准确性和最终任务完成率。
11. 对索引刷新失败、文档修订和失效材料建立可追踪的恢复流程。
12. 对涉及投资决定的报告保留人工复核和发布记录，不让 Agent 自动提交交易或调整组合仓位。

## 场景分析

投资经理问：“公司 A 最近两个季度盈利预期为何下调？我们是否需要减少持仓？”

Agent 从持仓 Semantic View 得到组合在 11 月 27 日持有公司 A 的市值和权重；从 Cortex Search 检索到两份同一券商的研究报告，分别发布于 9 月和 11 月；同时找到公司 10 月的正式业绩公告。

回答应先列出公司披露的实际业绩，再比较两版研究报告中的预测、假设和评级变化。若研究员将原油价格假设从 75 美元调到 85 美元，且下调了利润预测，应明确这是分析师情景假设；不要说成公司已经发生了同等幅度的利润下降。

最后再将最新持仓权重与当时有效的集中度政策比较，说明是否触发风险限额。是否减仓是投资经理和风险委员会的决策，Copilot 可以准备证据和敏感性分析，但不能替代审批。

## 常见误区

- **只用文件名识别发行人和版本。** 名称可能重复或变更，应有稳定 ID 和版本关系。
- **把发布日期与政策生效日期混为一谈。** 历史问题必须按当时有效的政策版本判断。
- **把分析师预测写成公司事实。** 预测、披露、市场数据和内部观点要分开标注。
- **把每份 PDF 切成等长文本块。** 财务表格、脚注和章节结构需要保留上下文。
- **先全量检索再让模型隐藏受限材料。** 权限应在可信检索层执行，不能依赖模型自我约束。
- **搜索未命中就断言没有相关风险。** 还要检查索引刷新、检索范围、元数据匹配和文件可解析状态。
- **把检索相似度当作引用正确性。** 关键数字要核对原始页码、期间、单位和来源版本。

## 完成标准

- [ ] 能为研究文件建立稳定身份、版本、发布日期和生效时间。
- [ ] 能解释文档切分时为什么必须保留标题、页码、表格和脚注。
- [ ] 能区分结构化事实与 Cortex Search 的非结构化证据。
- [ ] 能在检索前落实权限范围，并完成负向访问测试。
- [ ] 能区分公司披露、市场数据、分析师预测、内部观点和政策要求。
- [ ] 能对关键数字、评级变化和政策判断进行引用核查。

## 自测

1. 一份分析师报告在 11 月 20 日发布，投资政策在 12 月 1 日生效。回答 11 月 27 日的历史问题时，应使用哪一版政策？
2. 搜索结果显示“EBITDA 预计下降 8%”。如何判断这是公司披露、分析师预测还是内部模型估算？
3. 同一发行人有两份不同日期的研究报告。如何比较评级变化而不把不同机构或评级尺度混在一起？
4. 为什么不能让 LLM 从全量研究文档中自行隐藏用户无权访问的文件？
5. Search 没有找到最新研究报告。除了回答“没有评级变化”，还应检查哪些索引和来源状态？
