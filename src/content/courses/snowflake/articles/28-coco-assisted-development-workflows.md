# Snowflake CoCo：数据探索、SQL 生成与安全交付

## CoCo 的定位

CoCo 面向 Snowflake 数据开发任务，帮助开发者探索数据、理解代码、生成 SQL、构建管道和应用。它能减少查找和编写工作，但生成的 SQL、DDL、模型定义和权限配置仍然需要验证。把 CoCo 当作开发助手，而不是生产数据的最终责任人。

## 先给足仓库和对象上下文

让工具了解当前数据库、Schema、关键表定义、数据字典、依赖和业务目标。只提供必要的上下文，避免把不相关的全部对象和敏感数据送入 Agent。对大表探索先做采样、统计和范围限定。

## SQL 审查

生成 SQL 后检查是否使用正确的数据库、Schema 和对象；Join 键、结果粒度和过滤条件是否符合业务定义；是否产生全表扫描、笛卡尔积或不必要的重复计算；是否包含未授权的写入、删除或外部访问；是否能通过固定测试数据和 Golden Query；Query Profile 是否支持性能假设。

## 代码变更流程

将 AI 生成的变更放在分支中，阅读完整 Diff，执行 SQL lint、Schema 检查和数据验证。破坏性 DDL、权限变更和生产发布必须进入正常审查和部署流程。

## 工作流治理

将常用任务沉淀成版本化 Skill，限定输入、工具、预期输出和停止条件。记录使用的模型、工具版本、输入数据范围、生成变更和人工确认结果。技能包不能把未经验证的模型结论包装成平台事实。

## 业务安全

不要把真实客户敏感数据、凭据或生产连接信息放进 Prompt。CoCo 生成的外部访问、Procedure 或 Agent 工具需要单独做权限和网络审查。

## 检查题

1. 为什么 SQL 能成功运行还不能证明结果正确？
2. CoCo 生成 DDL 后，哪些变更需要重点审查？
3. 怎样让重复的 CoCo 工作流可复现、可审计？
