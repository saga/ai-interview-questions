# Query Profile 与弹性计算取舍

## 本节要解决的问题

区分单查询瓶颈、并发排队、扫描量和异常重型查询

Snowflake 工程交付与运维。重点是让配置、执行身份、变更、运行证据和恢复过程可重复、可审查、可追踪。

本教程只对应知识点 `snowflake-guide-query-diagnostics`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 区分单查询瓶颈、并发排队、扫描量和异常重型查询

诊断不能只看总耗时。应拆分编译、排队、执行和结果传输，再检查扫描量、过滤效率、Join 基数、排序/聚合、溢写和估算行数偏差。

- **误区：** 多集群扩容主要增加单查询算力

- **误区：** 纵向扩容保证所有查询更快更便宜
  **纠正：** 诊断不能只看总耗时。应拆分编译、排队、执行和结果传输，再检查扫描量、过滤效率、Join 基数、排序/聚合、溢写和估算行数偏差。
- **误区：** Query Profile 不能呈现执行算子
  **纠正：** 诊断不能只看总耗时。应拆分编译、排队、执行和结果传输，再检查扫描量、过滤效率、Join 基数、排序/聚合、溢写和估算行数偏差。
- **误区：** 查询慢时应先删历史表而非分析计划
