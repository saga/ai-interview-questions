# Semantic View 高级建模与诊断

## 本节要解决的问题

围绕事实粒度、关系基数、时间有效性、半可加指标和生成 SQL 诊断，构建可信的 Semantic View。

企业数据架构与治理。先定义业务实体、事实粒度、指标口径和访问责任，再决定物理模型、语义定义与权限策略。

本教程只对应知识点 `snowflake-coco-semantic-patterns`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 工程实施步骤

1. 写清业务实体、事实粒度、关系基数、指标口径、敏感级别和 owner。
2. 将业务定义映射到物理模型、语义对象、角色授权和数据质量规则。
3. 用 Golden Queries、允许/拒绝访问测试和变更审查验证结果。

## 常见误区

- **误区：** 未明确事实粒度就直接连接多个事实表，导致指标重复计数。
  **纠正：** 诊断不能只看总耗时。应拆分编译、排队、执行和结果传输，再检查扫描量、过滤效率、Join 基数、排序/聚合、溢写和估算行数偏差。
- **误区：** 把时点快照沿时间维度简单求和，造成业务指标失真。
  **纠正：** 诊断不能只看总耗时。应拆分编译、排队、执行和结果传输，再检查扫描量、过滤效率、Join 基数、排序/聚合、溢写和估算行数偏差。
- **误区：** 把语义查询的 SQL 解释或部署成功当作结果正确的证明。

- **误区：** 假设 YAML 与 DDL 的所有语义视图能力完全等价。
