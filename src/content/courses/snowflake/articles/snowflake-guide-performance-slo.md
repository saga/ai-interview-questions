# 以 SLO 与基线驱动性能工程

## 本节要解决的问题

把业务对数据查询和刷新体验的要求变成可测量的 SLO，并建立可比较的性能基线。性能目标需要同时覆盖响应时间、并发、吞吐和单位工作成本；一个仓库规格、一次最快查询或全天平均耗时都不能代表用户体验。

## 核心知识

### SLO 从消费者体验和业务工作负载定义

交互式 BI 关注 p95/p99 响应时间和并发；批处理关注完成窗口和数据新鲜度；数据产品关注交付延迟、可用性和结果质量。应明确测量对象、时间窗、分位数、错误率、样本量和排除条件。

例如，BI 的目标可以是高峰时段 p95 小于 5 秒且错误率低于 0.1%；夜间 ETL 的目标可以是 06:00 前完成且目标表新鲜度小于 30 分钟。这些目标必须由业务消费需求确定，而不是直接采用一个平均执行时长。

### 基线必须控制数据、缓存、并发和执行资源

Snowflake 查询表现受到数据规模与分布、SQL 版本、Warehouse Size、集群数、缓存状态、并发负载、Session 参数和网络影响。每次基准运行需要记录 Query ID、Query Tag、参数、数据时间点、Warehouse 和缓存条件。

冷缓存和热缓存应分别测量；单并发测试不能代替高峰并发基准。使用参数化查询或稳定的查询组识别同类工作负载，避免将不同查询类型混为一条趋势。

### 性能与成本、质量共同验收

改善响应时间可能增加 Warehouse credits；降低计算成本也可能扩大数据延迟。优化验收应同时看 p50/p95、错误率、排队、完成窗口、扫描量、spill、credits 和业务结果等价性。SLO 还应定义告警阈值、错误预算和超限后的升级路径。

## 工程实施步骤

1. 按消费者场景划分 workload：BI、ETL、临时分析、API 查询或共享数据产品。
2. 为每个 workload 定义 p95/p99、并发数、吞吐、数据新鲜度、错误率与单位成本的目标。
3. 从 Query History、Warehouse Load History 和业务监控收集至少一个代表性周期的基线，按高峰/非高峰分层。
4. 建立固定数据样本或可重复回放的查询集合，记录 SQL 版本、参数、Warehouse 规格、Query Tag 和缓存条件。
5. 冷缓存和热缓存分别执行基准；逐步增加并发，记录排队、执行和请求错误变化。
6. 每次只改变一个关键因素，如 SQL、Warehouse Size、Multi-cluster、数据聚簇或 Query Acceleration，避免结果无法归因。
7. 对比 p50/p95、吞吐、排队、扫描、spill、credits 和业务结果；达到性能目标但超出成本预算时不能直接验收。
8. 将基准放进版本发布流程；定义明显回归时停止推广或回滚到上一版本的阈值。
9. 生产环境持续按同一口径采集指标，避免开发环境的单次测试成为长期 SLO 依据。

## 场景分析

销售仪表板在测试环境中 p95 为 2 秒，生产高峰却超过 12 秒。测试环境使用小数据集、单用户和热缓存，生产则有 100 个并发用户、长时间运行的 ETL 和更多历史数据。

首先确认两端使用相同 SQL、参数和语义，再按缓存状态与并发分层复测。若生产 QUERY_HISTORY 显示 queued_overload_time 增长，优先检查工作负载隔离和 Multi-cluster；若执行时间增加且扫描量膨胀，检查数据规模、过滤与 Join；若两者同时存在，分别处理。性能目标应按生产高峰数据更新，不能继续引用测试环境的 2 秒数值。

## 常见误区

- **用平均时延定义所有用户的体验。** 尾部延迟和高峰负载常被平均值掩盖。
- **只记录 SQL 和 Warehouse Size。** 数据分布、缓存、Session 参数和并发也会改变基准结果。
- **把一次最短运行时间当性能 SLO。** SLO 需要稳定观察窗口、代表性样本和错误率约束。
- **只优化执行时间不看排队。** 用户感知的延迟还包括仓库预配、并发排队和事务等待。
- **以降低 credits 代替业务成功。** 成本变化应与数据质量、新鲜度和消费者体验共同验收。

## 完成标准

- [ ] 能从业务场景定义 p95/p99、并发、吞吐和数据新鲜度目标。
- [ ] 能为性能基准记录数据、缓存、Warehouse 与 SQL 版本。
- [ ] 能区分冷缓存、热缓存和高峰并发下的表现。
- [ ] 能用 Query History 和 Warehouse Load History 解释性能变化。
- [ ] 能定义成本和质量约束下的回归门禁与回滚条件。

## 自测

1. 测试环境 p95 为 2 秒，生产高峰 p95 为 12 秒，为什么不能直接据此断定 Warehouse 太小？
2. 性能基准中为什么要分别测冷缓存和热缓存？
3. 一项优化让 p95 降低 50%，但 credits 增加一倍，如何判断是否达到了业务 SLO？
4. CI 中性能测试该怎样固定数据、SQL 参数与并发条件？
