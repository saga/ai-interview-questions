# PostgreSQL 查询模式、全文搜索与扩展

## 本节要解决的问题

识别 N+1、SELECT *、深分页和索引列函数等常见查询反模式，并了解全文搜索、PostGIS、pgvector 等扩展的边界。

PostgreSQL 数据库工程。依据 PostgreSQL 自身的事务、MVCC、WAL、索引、优化器和后台维护语义分析问题，不将 Snowflake 机制套用到 PostgreSQL。

本教程只对应知识点 `postgresql-query-patterns-extensions`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 通过批量查询、投影和稳定分页方案减少无效往返与数据处理

半结构化和搜索能力要依据访问模式选择。频繁参与关联、约束和聚合的字段通常应明确建模；JSONB、数组、全文搜索和模糊匹配有不同边界。

### 区分 ILIKE/正则匹配、PostgreSQL 全文搜索与向量相似度检索的用途

检索系统要分别评估数据完整性、索引新鲜度、权限过滤、Recall@K/排序相关性和最终答案忠实度。命中一个文档不代表证据充分。

### 对扩展的安装、版本兼容、索引支持和运维依赖作显式评估

先用执行计划和运行证据识别扫描、过滤、缓存、Join 或排队瓶颈，再考虑聚类、索引、加速服务或重写。优化要对比延迟、扫描量和费用。

## 常见误区

- **误区：** 认为数据库增加索引就一定能消除应用侧 N+1 往返
  **纠正：** 先用执行计划和运行证据识别扫描、过滤、缓存、Join 或排队瓶颈，再考虑聚类、索引、加速服务或重写。优化要对比延迟、扫描量和费用。
- **误区：** 把全文检索、模糊字符串匹配和向量相似度视为同一种查询
  **纠正：** 检索系统要分别评估数据完整性、索引新鲜度、权限过滤、Recall@K/排序相关性和最终答案忠实度。命中一个文档不代表证据充分。
- **误区：** 认为扩展安装后就没有版本、资源和运行维护成本
  **纠正：** 半结构化和搜索能力要依据访问模式选择。频繁参与关联、约束和聚合的字段通常应明确建模；JSONB、数组、全文搜索和模糊匹配有不同边界。
