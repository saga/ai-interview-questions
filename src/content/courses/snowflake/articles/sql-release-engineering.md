# SQL 定义版本控制与环境发布

## 本节要解决的问题

将对象定义纳入 Git，通过审查、部署和漂移检测交付。

数据工程。将输入、摄取、转换、状态推进、目标写入和下游可见性分开观察；执行成功必须结合质量、重放能力和端到端延迟。

本教程只对应知识点 `sql-release-engineering`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 区分对象 DDL 与有状态迁移，设计发布与恢复方案。

平台短期恢复能力、零拷贝克隆和长期业务历史保存解决不同问题。恢复前记录时间点、对象范围和影响面，在隔离副本验证后再执行生产恢复。

### 密钥不入库，发布身份使用最小权限。

权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。

## 工程实施步骤

1. 记录源系统、文件/事件形态、业务键、事件时间、到达时间和批次标识。
2. 定义加载/转换状态、重复与迟到处理、拒绝数据隔离和失败后的可重放范围。
3. 核对目标行数、关键业务汇总、端到端新鲜度和重跑幂等性。

## 场景分析

订单源每天提供批次文件，部分事件会迟到、重复或被修订，下游报表需要稳定更新。请设计接入、处理、重放和结果核验路径。

将场景转换为明确输入、状态变化和预期输出。逐项检查本节核心要求，区分配置事实、运行证据和待验证假设。缺少权限、版本、数据样本或官方行为证据时，明确记录未知项，不用猜测补齐。

## 常见误区

- **误区：** 以手工生产状态代替版本历史。
  **纠正：** 可重复交付需要把版本源、目标环境、执行身份、依赖顺序、密钥、部署计划、测试证据和回滚路径连在一起。代码合并或 SQL 执行成功都不等于上线验证完成。
- **误区：** 将生产凭据提交到仓库。
  **纠正：** Snowflake 的存储、计算与 Cloud Services 属于不同责任边界。分别检查数据持久化、Warehouse 资源以及平台级元数据、认证与协调，不能把一个层次的设置当作另一个层次的修复手段。
