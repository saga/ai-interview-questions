# CoCo 辅助数据探索基础

## 本节要解决的问题

使用 Snowflake CoCo 辅助理解 Schema、生成探索查询和解释查询结果，同时避免把探索性分析误当成正式业务结论。探索阶段的目标是提出可验证假设、发现数据特征和确定下一步检查，而不是让 Agent 在未理解数据含义时直接生成生产逻辑。

## 核心知识

### 探索前先限定对象、范围和问题

给 CoCo 的请求应包含 Database/Schema/对象名、分析目标、时间范围、重要字段的业务含义和允许访问的数据范围。仅说“分析这个客户表”可能让它选错表、忽略历史版本或扫描过大的数据集。

在 Snowsight，CoCo Side Panel 可以读取当前 Worksheet、文件或页面的上下文；CoCo mode 更适合跨文件、仓库和多步骤任务。无论使用哪种入口，SQL 查询都使用当前活动 Role 的权限，不能通过自然语言提示绕过 RBAC。

### 先做低成本抽样，再逐步扩大分析范围

探索性查询应先检查表结构、行数、日期范围、空值分布、重复键和少量样本，再执行更昂贵的 Join、聚合或全量统计。采样只能帮助形成初步假设，不能代表完整数据分布；尤其需要关注长尾类别、稀有事件和时间偏差。

CoCo 可以解释 SHOW/DESCRIBE 结果、生成 profiling SQL、比较不同过滤条件和解释 Query Profile。但生成查询仍可能使用错误的 Join Key、过滤或日期口径，因此每一步都应检查 SQL 和实际返回结果。

### 探索结论需要区分观察、推断和待验证假设

例如“最近一个月退款数量上升”是观察；“退款政策调整导致退款增加”是推断，需要额外证据。CoCo 可以帮助归纳模式，但不能单靠相关性证明因果关系，也不能把抽样结果当作全量统计。

对于财务、风控和客户分层，先检查业务口径、样本覆盖、缺失数据和时间窗口，再对外发布结论。需要正式指标时，应转成经业务确认的 SQL、Semantic View 或数据模型。

## 工程实施步骤

1. 指定目标对象和业务问题，提供关键字段含义、时间范围和需要输出的统计。
2. 先用 SHOW TABLES、DESCRIBE TABLE 和 COUNT 等低成本查询确认对象结构与数据规模。
3. 让 CoCo 生成探索 SQL 后，检查列名、过滤边界、Join Key、聚合粒度和 LIMIT/SAMPLE 使用范围。
4. 按顺序检查空值、重复键、极值、类别分布和时间分布，保留查询 ID 与结果样本。
5. 对可能昂贵的 SQL 先使用有选择性的过滤和小范围测试，再查看 Query Profile 的扫描量、Join 输入输出和 spill。
6. 将抽样结论与全量统计区分；对长尾和稀有类别另行抽样，避免只查看前几条记录。
7. 对相关性结论补充分组、时间和混杂因素检查，不把关联关系直接写成因果关系。
8. 将验证过的查询整理为可复用 SQL 或 Golden Query，并记录数据时间点、参数和执行 Role。
9. 对正式指标或模型特征，要求业务 owner 确认口径后再转入生产代码。
10. 使用同一数据版本复测探索查询，保存假设、证据、结果和尚未验证的问题。

## 场景分析

分析人员发现某产品最近 30 天退款率比前一个月高，希望判断是否由新供应商造成。CoCo 可以协助生成按日期、供应商和产品分组的查询，但不能直接认定供应商导致退款上升。

先验证退款率分子/分母、订单完成时间与退款时间口径；再检查样本量、产品组合变化、供应商分布和数据缺失。按供应商分组比较时，需控制产品类别和订单规模差异。若只抽样最近 100 条记录，不能据此推断整体退款率。

验收要求统计结果能从固定 SQL 重现，记录 Query ID 和数据时间范围，并将“供应商相关性”与“供应商导致退款”的待验证假设分开。

## 常见误区

- **让 CoCo 自己猜业务表和字段含义。** 需要明确对象、粒度和业务口径。
- **把 LIMIT 结果当代表性样本。** 默认返回前几行可能有排序或存储偏差。
- **用抽样分布得出全量结论。** 稀有事件、长尾类别和时间偏差需要额外验证。
- **把相关性解释成因果。** 还要检查时间、产品组合、用户结构和其他影响因素。
- **只看查询执行速度。** 结果语义和数据质量比单次运行时间更重要。
- **让探索查询直接成为生产指标。** 正式指标仍需 owner 确认、回归测试和版本管理。

## 完成标准

- [ ] 能为 CoCo 提供对象、字段含义、时间范围和业务目标。
- [ ] 能设计从结构检查到分布分析的低成本探索步骤。
- [ ] 能识别抽样偏差、长尾和时间窗口风险。
- [ ] 能从 Query Profile 发现探索查询的扫描和 Join 问题。
- [ ] 能区分观察、推断和待验证假设。

## 自测

1. CoCo 只查询前 100 行并发现没有 NULL，是否能够说明整张表没有 NULL？
2. 某供应商退款率上升，怎样区分供应商因素与产品组合变化？
3. 为什么探索查询应先检查 Join Key 和行粒度，再开始聚合？
4. 在探索阶段使用 LIMIT 或 SAMPLE 时，应当如何记录其证据边界？
5. 何时应该把探索 SQL 转成正式 Semantic Metric 或生产模型？
