# Marketplace、数据共享与应用交付

## 本节要解决的问题

将受治理的数据能力发布为可复用产品，区分跨账户共享、应用分发与交互式 UI。

数据产品与应用交付。把提供方、消费者、应用身份、数据契约、版本、授权和生命周期作为同一产品边界。

本教程只对应知识点 `snowflake-data-products`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 按消费者访问方式评估共享/Marketplace、Streamlit 或 Native Apps

Stream 暴露的是自上次消费位置以来的变更视图，消费进度与事务提交相关。需要明确消费事务、目标幂等键和失败恢复流程，不能把它当无限期完整变更日志。

### 定义 owner、版本、消费契约与升级/撤销流程

数据产品要明确 Provider 与 Consumer 的责任、共享对象范围、调用身份、数据契约、版本兼容、更新频率、支持渠道和撤销方式。

### 验证应用身份和消费者实际可访问的对象

数据产品要明确 Provider 与 Consumer 的责任、共享对象范围、调用身份、数据契约、版本兼容、更新频率、支持渠道和撤销方式。

## 工程实施步骤

1. 定义 Provider、Consumer、应用身份、可访问对象和数据契约。
2. 准备版本、更新频率、质量指标、升级/弃用策略和支持责任。
3. 使用消费者真实身份测试安装、读取、导出、权限拒绝和撤销流程。

## 场景分析

数据团队准备把内部数据集交付给外部消费者。请明确发布身份、消费权限、数据契约、版本兼容和撤销流程。

将场景转换为明确输入、状态变化和预期输出。逐项检查本节核心要求，区分配置事实、运行证据和待验证假设。缺少权限、版本、数据样本或官方行为证据时，明确记录未知项，不用猜测补齐。

## 常见误区

- **误区：** 把 Streamlit UI 当底层安全边界
  **纠正：** Stream 暴露的是自上次消费位置以来的变更视图，消费进度与事务提交相关。需要明确消费事务、目标幂等键和失败恢复流程，不能把它当无限期完整变更日志。
- **误区：** 认为 Marketplace 发布自动解决版本治理
  **纠正：** 可重复交付需要把版本源、目标环境、执行身份、依赖顺序、密钥、部署计划、测试证据和回滚路径连在一起。代码合并或 SQL 执行成功都不等于上线验证完成。
- **误区：** 默认跨账户共享只能复制数据
  **纠正：** 数据产品要明确 Provider 与 Consumer 的责任、共享对象范围、调用身份、数据契约、版本兼容、更新频率、支持渠道和撤销方式。
