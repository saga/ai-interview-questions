# Snowpark DataFrame 转换与优化

## 本节要解决的问题

使用 Snowpark DataFrame 组合转换，结合惰性执行、SQL 下推、连接粒度和 Query Profile 进行诊断。

数据工程。将输入、摄取、转换、状态推进、目标写入和下游可见性分开观察；执行成功必须结合质量、重放能力和端到端延迟。

本教程只对应知识点 `sf-demo-snowpark-dataframe`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 区分 transformation 与触发执行的 action

先判断逻辑是集合式数据转换、单值计算还是多步骤过程控制。分别评估 SQL、Snowpark、UDF 和 Procedure 的运行时、依赖、权限、副作用、部署测试与可观测性。

### 在连接和聚合前定义数据粒度并核查连接基数

业务指标必须定义分子、分母、过滤条件、时间口径、事实粒度和可加性。语义层能表达已确认的业务定义，却不能修复底层错误键、粒度或多对多关系。

### 以实际查询计划、扫描量、spill 与结果对账验证优化

诊断不能只看总耗时。应拆分编译、排队、执行和结果传输，再检查扫描量、过滤效率、Join 基数、排序/聚合、溢写和估算行数偏差。

## 工程实施步骤

1. 记录源系统、文件/事件形态、业务键、事件时间、到达时间和批次标识。
2. 定义加载/转换状态、重复与迟到处理、拒绝数据隔离和失败后的可重放范围。
3. 核对目标行数、关键业务汇总、端到端新鲜度和重跑幂等性。
