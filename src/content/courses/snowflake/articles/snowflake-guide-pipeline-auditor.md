# Pipeline Auditor 与结构化健康检查

## 本节要解决的问题

对不同类型的数据平台对象运行健康检查并输出分级调查报告

Cortex Agents、ML 与 CoCo。明确目标、工具/模型边界、身份授权、输入输出、执行证据、评测和停止条件。

本教程只对应知识点 `snowflake-guide-pipeline-auditor`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 对不同类型的数据平台对象运行健康检查并输出分级调查报告

落实时将这项要求放到实际输入、输出和运行上下文里验证。Cortex Agents、ML 与 CoCo。明确目标、工具/模型边界、身份授权、输入输出、执行证据、评测和停止条件。

### 限定审计范围，调用受限检查工具并返回证据、时间戳与 severity 字段

Agent 可靠性来自工具契约、调用身份、权限、停止条件、失败恢复和可审计轨迹。Thread 不是业务状态库；工具返回内容是待验证数据，不是系统指令。

### 限制审计范围和工具权限，把建议与生产改动分开审批

权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。

## 工程实施步骤

1. 将用户目标拆成可验证步骤，定义工具输入输出、身份、权限和停止条件。
2. 记录模型/工具版本、执行轨迹、失败状态、重试次数和业务幂等键。
3. 分别评估任务结果、工具选择、证据质量、越权拒绝、恢复能力和成本。

## 场景分析

用户要求 Agent 完成包含检索、分析和工具执行的任务。请定义工具选择、权限、执行轨迹、错误恢复和完成条件。

将场景转换为明确输入、状态变化和预期输出。逐项检查本节核心要求，区分配置事实、运行证据和待验证假设。缺少权限、版本、数据样本或官方行为证据时，明确记录未知项，不用猜测补齐。

## 常见误区

- **误区：** 语言解释流畅便可省略原始运行数据
  **纠正：** 回到本知识点的输入条件、执行边界和验证证据，确认判断成立的前提，不要把简化经验当普遍规则。
- **误区：** 缺状态时由模型补齐根因
  **纠正：** 机器学习流程要保存训练数据版本、特征定义、时间点、代码和模型版本，并使用独立验证集评估。避免未来信息泄漏；模型注册不等于业务效果已验收。
- **误区：** 覆盖更多对象就无需限制查询权限
  **纠正：** 权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。
- **误区：** 诊断与生产修复无需区分
  **纠正：** 诊断不能只看总耗时。应拆分编译、排队、执行和结果传输，再检查扫描量、过滤效率、Join 基数、排序/聚合、溢写和估算行数偏差。
