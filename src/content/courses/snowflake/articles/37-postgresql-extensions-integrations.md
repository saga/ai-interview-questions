# PostgreSQL 扩展、全文搜索与平台集成边界

## 扩展机制

PostgreSQL Extensions 可以增加数据类型、操作符、函数、索引访问方法和后台能力。常见扩展包括 pg_stat_statements、pg_trgm、PostGIS 等。扩展会引入版本、安装权限、升级和备份兼容要求，应纳入数据库变更管理。

## 全文搜索与模糊匹配

全文搜索通常通过 tsvector 和 tsquery 建立语言相关的词项检索；GIN 索引适合加速匹配。pg_trgm 提供基于三元组的相似度和模糊匹配能力。选择方案要根据语言、分词、拼写容错、相关性和维护成本决定，不要把它们当成通用向量检索替代品。

## 外部连接与集成

应用通过驱动或连接器访问数据库，常见连接方式包括 libpq、JDBC、ODBC 和语言驱动。连接参数、TLS、认证、超时、连接池、重试和事务边界应统一管理。对于跨数据库读写，不要假设两个系统的事务能够自动原子提交。

## PostgreSQL 与 Snowflake 的边界

在同一数据平台项目中，PostgreSQL 常承担事务型系统或应用数据库角色；Snowflake 更常承担分析、历史汇总和数据产品角色。数据同步应明确 CDC 来源、删除语义、时间字段、幂等键和延迟目标。不要把 PostgreSQL MVCC、WAL、VACUUM 和索引内部机制解释成 Snowflake 的实现。
