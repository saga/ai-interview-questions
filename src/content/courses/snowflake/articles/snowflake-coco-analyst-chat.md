# Cortex Analyst 与数据问答应用

## 本节要解决的问题

面向 Snowflake 新建的多步骤自然语言数据应用，应优先评估 Cortex Agents 作为编排层：它可调用 Cortex Analyst 处理结构化指标与 Text-to-SQL，并调用 Cortex Search 处理文档检索。Semantic Views 和已验证查询可继续复用；独立 Cortex Analyst API 仍可用，适合已有集成或聚焦的结构化分析路径。

Cortex GenAI 应用。明确任务输入、模型或检索路径、输出契约、质量指标、数据权限和失败处理。

本教程只对应知识点 `snowflake-coco-analyst-chat`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 常见误区

- **误区：** 把所有自然语言数据问答都当成同一种检索任务处理
  **纠正：** 模型输出先作为候选结果处理。分别验证格式/Schema、业务不变量、证据来源、低置信结果和异常样本，并记录模型/提示版本、输入范围、延迟和成本。
- **误区：** 把 Cortex Analyst 或 Cortex Search 单独当作覆盖结构化和非结构化任务的通用编排层
  **纠正：** 调度成功只说明执行器完成触发，不代表业务数据已正确交付。还要检查依赖、执行身份、重叠运行、失败重试、下游可见性和数据质量。
- **误区：** 未检查一对多 JOIN 就相信 SQL 聚合与生成结果
  **纠正：** 模型输出先作为候选结果处理。分别验证格式/Schema、业务不变量、证据来源、低置信结果和异常样本，并记录模型/提示版本、输入范围、延迟和成本。
- **误区：** 认为模型只要看到列名就能稳定推断业务指标和同义词
  **纠正：** 业务指标必须定义分子、分母、过滤条件、时间口径、事实粒度和可加性。语义层能表达已确认的业务定义，却不能修复底层错误键、粒度或多对多关系。
- **误区：** 认为独立 Cortex Analyst API 已经不可用，或迁移必须重建语义视图
  **纠正：** 业务指标必须定义分子、分母、过滤条件、时间口径、事实粒度和可加性。语义层能表达已确认的业务定义，却不能修复底层错误键、粒度或多对多关系。
