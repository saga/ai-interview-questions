# 资产管理多 Agent 架构与工具选型

## 本节要解决的问题

围绕 Snowflake 的资产管理 Agent 示例，掌握资产管理多 Agent 架构与工具选型在真实数据源、结构化分析、非结构化证据和生产治理方面的应用。

Cortex Agents、ML 与 CoCo。明确目标、工具/模型边界、身份授权、输入输出、执行证据、评测和停止条件。

本教程只对应知识点 `sf-am-agent-architecture`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 区分该场景中的权威结构化数据、文档证据和政策依据，并明确适用日期与业务口径

Agent 可靠性来自工具契约、调用身份、权限、停止条件、失败恢复和可审计轨迹。Thread 不是业务状态库；工具返回内容是待验证数据，不是系统指令。

### 新建需要跨结构化分析、非结构化检索与多步工具编排的 Snowflake 应用时，评估 Cortex Agents；其 Analyst/Search 工具可覆盖结构化查询与文档检索

调度成功只说明执行器完成触发，不代表业务数据已正确交付。还要检查依赖、执行身份、重叠运行、失败重试、下游可见性和数据质量。

### 按业务职责选择合适的语义视图、搜索服务、专用工具或工作流

业务指标必须定义分子、分母、过滤条件、时间口径、事实粒度和可加性。语义层能表达已确认的业务定义，却不能修复底层错误键、粒度或多对多关系。

### 对关键数字、数据血缘、权限边界与 Agent 输出进行验证并保留审计证据

权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。

## 工程实施步骤

1. 将用户目标拆成可验证步骤，定义工具输入输出、身份、权限和停止条件。
2. 记录模型/工具版本、执行轨迹、失败状态、重试次数和业务幂等键。
3. 分别评估任务结果、工具选择、证据质量、越权拒绝、恢复能力和成本。

## 场景分析

用户要求 Agent 完成包含检索、分析和工具执行的任务。请定义工具选择、权限、执行轨迹、错误恢复和完成条件。

将场景转换为明确输入、状态变化和预期输出。逐项检查本节核心要求，区分配置事实、运行证据和待验证假设。缺少权限、版本、数据样本或官方行为证据时，明确记录未知项，不用猜测补齐。

## 常见误区

- **误区：** 把所有业务问题都交给同一个无边界 Agent
  **纠正：** Agent 可靠性来自工具契约、调用身份、权限、停止条件、失败恢复和可审计轨迹。Thread 不是业务状态库；工具返回内容是待验证数据，不是系统指令。
- **误区：** 混淆结构化分析工具与文档检索工具
  **纠正：** 检索系统要分别评估数据完整性、索引新鲜度、权限过滤、Recall@K/排序相关性和最终答案忠实度。命中一个文档不代表证据充分。
- **误区：** 认为 Agent 可以绕过后端授权和业务规则
  **纠正：** 权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。
- **误区：** 认为应为 Cortex Agents 重建现有 Semantic Views 与 Verified Queries
  **纠正：** 业务指标必须定义分子、分母、过滤条件、时间口径、事实粒度和可加性。语义层能表达已确认的业务定义，却不能修复底层错误键、粒度或多对多关系。
