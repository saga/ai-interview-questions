Snowflake 工程交付与运维。重点是让配置、执行身份、变更、运行证据和恢复过程可重复、可审查、可追踪。

## 工程实施步骤

1. 明确 Git 版本、目标环境、部署身份、对象依赖和所需权限。
2. 先在低风险环境生成变更计划并运行静态、集成和数据验证。
3. 发布后核对对象定义、实际数据、运行指标和回滚点。

- **误区：** DCM 定义只用于文档不参与部署

- **误区：** 手工改生产会自动更新 Git

- **误区：** 声明式部署不会删除或替换对象
  **纠正：** 可重复交付需要把版本源、目标环境、执行身份、依赖顺序、密钥、部署计划、测试证据和回滚路径连在一起。代码合并或 SQL 执行成功都不等于上线验证完成。
- **误区：** 所有环境都应共用生产配置和权限
  **纠正：** 权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。
