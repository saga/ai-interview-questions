# Semantic Views 与 Cortex Analyst

## 本节要解决的问题

通过语义视图维护统一指标、维度、关系和查询边界，验证 Text-to-SQL 的业务语义。

企业数据架构与治理。先定义业务实体、事实粒度、指标口径和访问责任，再决定物理模型、语义定义与权限策略。

本教程只对应知识点 `sf-demo-semantic-analyst`。目标是理解其机制、适用边界和验证方法，不把相邻知识点合并成一个大章。

## 核心知识

### 定义统一业务指标、维度、粒度和关系路径

业务指标必须定义分子、分母、过滤条件、时间口径、事实粒度和可加性。语义层能表达已确认的业务定义，却不能修复底层错误键、粒度或多对多关系。

### 检查连接基数与重复计数

业务指标必须定义分子、分母、过滤条件、时间口径、事实粒度和可加性。语义层能表达已确认的业务定义，却不能修复底层错误键、粒度或多对多关系。

### 用黄金问题、预期结果、授权测试验证生成 SQL

权限判断沿用户、当前激活角色、角色继承、对象权限和所有权追踪，并检查 Database、Schema 与目标对象的使用权限。

## 工程实施步骤

1. 写清业务实体、事实粒度、关系基数、指标口径、敏感级别和 owner。
2. 将业务定义映射到物理模型、语义对象、角色授权和数据质量规则。
3. 用 Golden Queries、允许/拒绝访问测试和变更审查验证结果。
