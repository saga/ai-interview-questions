# Cortex AI Functions 与文档智能处理

## 在数据平台内执行 AI 任务

Cortex AI Functions 将模型推理能力与 SQL 工作流结合，适用于分类、摘要、信息提取、文本理解和模型调用等任务。函数名称、模型可用性、区域支持和计费规则可能随平台更新，应在项目开始时核对当前官方文档和账户可用模型。

不要把模型调用放到每条业务查询的热路径中，除非延迟、成本和失败处理已验证。批量分析应按批次运行，记录输入版本、模型标识、提示模板版本和调用结果。

## 结构化抽取

对合同、发票、采购单或工单，可把文档解析为字段，再进入强类型表。输出应包括原文定位、抽取值、置信或校验结果以及失败原因。模型生成的 JSON 即使能通过语法解析，也不一定符合业务约束。

## 质量控制

- 格式校验：字段存在、类型正确、枚举合法。
- 业务校验：金额合计、日期顺序、合同编号、币种和关联实体一致。
- 人工抽检：对高风险字段和低置信结果抽查原文。

对无法确定的值保留 NULL 或审核状态，不要让模型填补不存在的信息。

## 模型任务选型

简单分类或提取优先评估任务型函数；复杂推理和长文本任务才考虑通用模型。选择依据包括准确率、上下文长度、语言支持、延迟、吞吐、成本、数据治理和可复现性。

## 安全与成本

明确哪些数据允许送入模型服务，敏感字段是否需要脱敏，结果是否允许持久化。建立预算、批次大小、重试次数和错误隔离策略。模型调用失败不得让数据批次处于无法判断的中间状态。

## 检查题

1. 为什么模型输出通过 JSON Schema 仍然不代表业务正确？
2. 任务型函数与通用模型调用应如何分工？
3. 文档抽取结果需要哪些来源证据和业务校验？
