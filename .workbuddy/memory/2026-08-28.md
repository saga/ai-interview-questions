## 让 Agent 面试支持 Chrome 内置 AI
- 根因：Agent 循环依赖 pi-agent-core 的 `streamFn` 返回「带 toolCall 的事件流」，而 Chrome Prompt API 是纯文本 one-shot 补全，无原生 function calling；`runtime.buildAgentRuntime` 对 chrome 走 pi-ai `buildModels` 会落到 local provider 且 `getModel` 返回 undefined → 抛错 → 面试启动失败（"Agent面试点不了"）。
- 方案：新增 `src/ai/chromeAgent.ts`，实现 prompt-based 工具调用——把工具定义(JSON Schema)注入提示词，要求模型输出单个 JSON 工具调用，再解析成 `start→toolcall_*→done(toolUse)` 事件流；错误/解析失败回落为文本(stop)或 error 事件（触发既有的 ensureQuestionDelivered 自愈兜底）。
- `runtime.buildAgentRuntime` 在 `entry.id==='chrome'` 时改走 `buildChromeAgentRuntime()`；开放题评分本就经 `ChromeAIProvider`（provider 层已支持），无需改动。
- 测试 `src/ai/chromeAgent.test.ts`（5 例：合法 JSON 工具调用 / 非 JSON 文本 / 未知工具名 / chrome 不可用 error 事件 / 占位 model）。全量 363 passed，tsc 通过。
- 关键约束：事件流 `done`/`error` 即终止（参考 faux provider，不需 end()）；`Context.tools/systemPrompt` 由 agent-loop 正确传入。

## Chrome 并发策略调整：串行 → 最多 2 并发
- 原因：之前为规避本地模型并发 create 排队/QuotaExceededError，把 `chromeComplete` 改成模块级完全串行（`runSerialized`）；用户要求提高吞吐，放宽到 2 并发。
- 改动 `src/ai/chrome.ts`：移除 `chain` 串行链，新增 `CONCURRENCY=2` + `activeCount` + `pending` 队列 + `pump()`；`runLimited()` 投入队列，单任务成败只影响自身 promise（不阻塞其他任务）。
- 测试 `chrome.test.ts` 并发断言改为 `maxActive` 上界 ≤2 且 ≥2（证明非退化成串行）。全量 363 passed，tsc 通过。
