# 2026-10-02

## `npm run test` 失败 → 修复（5 项失败 → 871/871 全绿）

起点：HEAD 已从 `6109723` 前进到 `3f37b1e`（上一轮 ADR-086 的 22 个文件已被提交）。
`npm run test` 报 5 项失败，两类成因独立。

### 1. 失效的模型 id（3 项失败）

`在引擎 "deepseek" 中未找到模型 "deepseek-v4-flash"`。

- 查证：`npm pack @earendil-works/pi-ai@0.87.1` 到临时目录，读
  `package/dist/providers/data/deepseek.json`。0.87.1 与 1.0.0 的目录**都只有**
  `deepseek-flash`（DeepSeek V4.1 Flash）与 `deepseek-v4-pro`，**都没有** `deepseek-v4-flash`。
  该改名由 `e22ade3`（引入 `^0.87.1`）带入。
- **改名前先确认版本无关**：`deepseek-flash` 在两个版本里都在 → 改名对 0.87.1 / 1.0.0 均成立，
  不依赖工作区那份未提交的 1.0.0 升级。
- **更正上一轮的判断**：ADR-086 记的「零运行时引用」是错的。`src/config/sample-config.json`
  经 `config/sampleConfig.ts` → `storage/settings.ts` 的 `DEFAULT_CONFIG`，是运行时默认配置
  （`loadConfig()` 无存档时的回退 + 设置页「恢复默认」）。当时只 grep 了 `src/` 的 `.ts`/`.tsx`，
  漏了 `.json`。
- 改动：`src/config/sample-config.json` + 5 个测试文件（`ai/local.test.ts`、`ai/provider.test.ts`、
  `ai/providerSystem.test.ts`、`storage/settings.test.ts`、`schemas/ai-config.test.ts`）+
  `docs/config.example.json`（3 处 + 说明文字）+ `docs/ARCHITECTURE.md`。

### 2. 并行满载下的 5s 超时（2 项失败）

`ai/local.test.ts` 与 `ai/provider.test.ts` 的端到端用例 `Test timed out in 5000ms`。

- 单跑这两个文件：**1172ms / 784ms**，全过 → 是负载抖动，不是逻辑问题。
- 全量 65 文件并发，每个 worker 都要 import 6MB pi-ai dist（全量 `import` 累计 ~357s）。
- 修法：`vitest.config.ts` 设 `testTimeout: 20000` / `hookTimeout: 20000`。
  这两个用例 fetch 全部 mock、不依赖真实网络，提高超时不会掩盖真实故障。
- 这 2 项在 ADR-084 的验证记录里就出现过（「并行负载超时 2 项，单独跑全过」）。
