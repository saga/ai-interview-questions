## docs/知识和相关研究解析.md 纯格式重构（用户要求「整理格式，不动内容」）

1447 行 → **984 行**，全部文字内容保留，只改排版。

原始格式病（这类长文 LLM 初稿的通病，下次直接按此清单查）：
1. **H1 泛滥**：除标题外还有 23 个 `#`（引言/一~二十一/结论），H2/H3 混用无规律。
2. **换行碎片化**：几乎一句一行，段落被切碎。
3. **LaTeX 滥用**：`$$\text{Reasoning Path}$$`、`$$Score = 78$$` 这类单词也用独立公式块。
4. **引用块滥用**：定义、普通陈述都用 `>`。
5. **扁平枚举塞进 ` ```text `**（Layer 1~4 的实体/工具/概念/流程列表）。
6. **`---` 泛滥**（30+ 处），标题已能表达结构。

采用的收敛规则（可复用）：
- 层级：`#` 仅文档标题；章节 → `##`；子章节 → `##`+1 级 `###`；并行示例标签（Recall/Apply/Decision…）**不用标题**，改**加粗**。
- LaTeX：**单个简单表达式 → 行内 `$...$`**（如 `$Score = 78$`、`$Question\ Coverage$`）；**多行/复合公式才用 `$$` 块**；纯概念词（Reasoning Path / Surface Text）改**加粗**不用公式。
- 代码块：只保留**有层级/对齐结构**的 ASCII 图（树形、矩阵、管线）；**扁平枚举 → markdown 列表**。
- 引用块：只保留**真·引用/示例题目**；定义性语句改普通段落或加粗。
- 全文件**删掉所有 `---`**；列表符号统一 `-`。

**遗留内容问题（未改，属内容范畴，待用户决定）**：§一 标题写「区分**四个**经常被混为一谈的东西」，但正文只列了 **3 个**（Knowledge / Concept / Skill-Competency），疑似缺第 4 项。

### 第二轮：去「AI 味」（用户再反馈「单词罗列 + ASCII 箭头图太多」，仍要求不改语义）
984 行 → **370 行**。核心是**把 LLM 腔的两种典型载体换掉**：

- **ASCII 图全清零**（原 24 处 ` ```text ` 块，`grep '^```'` 结果为 0）：
  - 树形/流程/管线 → **散文叙述**（用「从 A 到 B，中间经 C」的中文句式，术语保留英文原词）。
  - 线性链路 → **行内 code**，如 `` `Document → Knowledge Extraction → ...` ``，不再占块。
- **术语罗列清单 → 散文**：Bank/Fund/Issuer… 这类 9 项 bullet 改成一句「包括 Bank、Fund、… 等参与主体」。
- **有 2 个属性的清单 → markdown 表格**（共 8 张表）：
  Q-matrix 矩阵、Learner 掌握状态、四层模型、KV Cache 七层级示例、变体形态、Layer 5 能力、Duration 示例题（层级/题干/定位）、Misconception 四条。

**去 AI 味通用手法（可复用）**：
1. 长 bullet 清单 → 合并成带「包括/覆盖/即」的整句散文；
2. ASCII 树/箭头图 → 散文或表格，**基本没有必须保留 ASCII 的场景**；
3. 单列术语 → 行内 code 或散文；双属性 → 表格；
4. 公式只留真数学，概念链路用行内 code；
5. 段落长短交错，别让每段都是 1–2 句（AI 腔的典型节奏）。

## 第五轮：第三轮审核意见（6 条 + Item Specification 拆分），437 → 510 行

**P0**
1. **Knowledge Attribute 定义收紧**（§2）：不能再只说"为诊断目的定义的测量变量"。改为三限定——为特定诊断目的「定义」出来的（不是知识天然原子；CDM 是把它与 item/task performance 建随机关系，不是把 KG 节点搬来当 latent）；必须**可由一组 item 的作答模式识别**；并非所有 Concept 都需建模成 Attribute。KV Cache 例子改为「能识别 KV Cache 显存占用的主要决定因素」。
2. **`Knowledge Graph → Knowledge Attributes` 不是 Q-matrix 前提**（§6）：Q-matrix 本质是 $Q_{ij}=1$，只规定 item 与 attribute 的必要性关系，不要求 attribute 派生自 KG；KG 是**上游助力而非必要前置**；Tatsuoka rule-space 强调的是从 response 识别错误规则，不是"必须先建 KG"。
3. **Knowledge Identity 改定义**（§5）：**不再用"同一 Concept / Attribute 集合"**（会把 Concept 与 Attribute 绑太死——同一 Concept 下不同 diagnostic attribute 切换可能已跨出去）。改为 **declared knowledge boundary**：可改 reasoning path / cognitive task / target，但不能把主要被测知识迁出原 Blueprint 的知识边界。落到 `assessment.reasoningGoal`。

**P1**
4. **Evidence Criterion vs Scoring Rubric 分工**（§3 新增小节）：上下游而非并列，$Target → Evidence Criterion → Scoring Rubric → Evidence$。一句话区分——前者定义"需要出现什么证据"，后者定义"这些证据如何被评分"。EC  belongs 在 Blueprint（测量意图），Rubric 在 Scoring（评分实现）。
5. **IRT 精度**：改为"用 item parameters 与 latent trait 对 response 建模；难度/区分度是不同模型的典型参数，非所有模型同参数化（Rasch vs 2PL/3PL）"。
6. **Interview Capability 不是第三种 state**（§14 + 引言）：$Performance = f(Knowledge\ State,\ Competency\ State,\ Interview\ Context)$。State 只留在 learner 侧两个维度；capability 无法脱离情境独立估计。

**额外采纳**：§3 新增 `Blueprint → Item Specification → Item` 拆分（Blueprint 答"测什么"，Item Specification 答"这次怎么出题"）。**不引入新领域对象**——本 repo 中它隐含在 Blueprint 的 `Constraints` 里，分离它让「一 Blueprint 多 Item」有了实现路径。结论补了一份 boxed 主链路。
