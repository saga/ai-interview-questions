## 项目：AI 面试题训练器（ai-interview-questions）
从零搭建的 React 应用，技术栈与关键决策：
- **栈**：Vite + React 18 + TypeScript + Ant Design（实际装到 antd 6.6.1，非 v5）。
- **LLM 集成**：`@earendil-works/pi-ai@0.84.2`（npm 最新；旧文档的 `^0.4.10` 不存在）。
  - `complete()` 的 options 类型不含 `apiKey`；浏览器注入密钥走 `createModels({ credentials })` 传入内存 `CredentialStore`（read 返回 `{type:'api_key', key}`）。
  - provider id 固定为 `openai`/`anthropic`/`openrouter`，与 `getModel(provider, id)` 对应。
  - pi-ai 已对浏览器做兼容（`globalThis.process` 守卫、懒加载 `node:fs`），不会因 env/fs 崩溃。
- **题库**：`src/data/questions.json`，28 题，8 类别，含 single/multiple/essay 三类。
- **AI 功能**：出题变体（重新措辞+打乱选项+重算答案索引）、问答题评分（0-100 + 亮点/遗漏）。
- **CORS 提示**：浏览器直连 OpenAI/Anthropic 可能受限，默认推荐 OpenRouter。

## 接入 pi-agent-core（Interview Agent 层）+ Vitest（用户确认：纯浏览器 local-first + 一并搭测试）
- 用户给出 pi-agent-core 评审结论：**Quiz Domain 自写，pi-agent-core 只做 LLM Agent 层**；变体留在 pi-ai（one-shot 不需要 Agent）。确认运行形态 = 纯浏览器 local-first（无后端）、一并搭 Vitest。
- 核实：`pi-agent-core@0.84.2` 依赖 `pi-ai@^0.84.2`，engines node>=22.19.0；**不**静态 import `pi-ai/compat`（旧 issue #6851 场景已不存在）；但 dist 顶层 import `node:crypto/fs/os/path/readline/url`，Vite 浏览器构建 externalize 成警告（只用 Agent 不触 harness 则不崩），主 chunk 1.26MB/369KB gzip，provider 代码为懒加载 chunk。
- 事件协议：`StreamFn=(model,context,options)=>AssistantMessageEventStream`，流事件 `start→text_delta(delta)→done(message with stopReason)`；Agent 把 text_delta 包成 `message_update` 事件（`event.assistantMessageEvent.delta`）。mock streamFn 必须产出 `done`，否则 `waitForIdle` 挂起。
- `Agent` 构造：`new Agent({ initialState:{systemPrompt,model}, streamFn })`；`agent.prompt(text)`/`agent.waitForIdle()`/`agent.subscribe()`/`agent.state.messages`。`Model` 类型从 pi-ai 导入（pi-agent-core 不导出），且 `Model` 需泛型参数 `Model<any>`。
- 落地：`ai/interviewAgent.ts`（唯一依赖 pi-agent-core；`(model,streamFn)` 依赖注入便于 mock 测试；`buildEvalUser`/`parseEvaluation` 纯函数导出）+ `ai/variantGenerator.ts`（变体，pi-ai one-shot）+ `ai/models.ts`（原 client.ts 更名，导出 buildModels/getModel/callLLM/extractJSON）+ `provider.ts` 内 PiAIProvider 委托。删除 `client.ts`/`piProvider.ts`。
- 评分维度更名：correctness/completeness/**architecture**/communication（原 depth/clarity），默认 0.4/0.2/0.2/0.2；`Question.rubric`（required 要点 + dimensions 权重覆盖，PiAIProvider 合并进全局 rubric）；题库 5 题补 rubric。
- Vitest：`npm run test`=vitest run；vitest.config.ts 独立（node 环境）；`*.test.ts` 从 tsconfig.app.json exclude（不参与 tsc -b）。33 用例全过：domain(quiz/evaluation/variant) + ai(interviewAgent 纯函数 + 真实 Agent + mock streamFn 集成)。
- 验证：`npm run test` 33/33；`npm run build` 通过；dev server 对 interviewAgent/models 转译 200。AGENTS.md 补"mock streamFn 协议"约定。

## 产品转向 Training Coach（用户评审：从 Quiz Configurator 转成 Training Coach）
- 用户核心诉求：首屏=训练入口（不是配置中心）；隐藏系统内部概念（评分权重、API Key 大 Alert）；API Key 移入设置页；Learner Memory + History + Recommendation 是本轮核心（localStorage 足够）。
- 落地：
  - 四页导航（训练/进度/面试/设置，antd Menu horizontal）。首屏 TrainingHome：继续训练（按薄弱项）/ 快速训练（10 分钟自动选题）/ 自定义训练（Collapse 折叠高级配置）。评分权重 UI 删除。
  - `domain/learner.ts`（纯函数）：updateLearner（topicStats 聚合 avgScore/mastery/trend/commonWeaknesses，会话上限 50，overall=最近10次均值）、sessionFromQuiz、recommendWeakTopics（mastery<0.85 且 avgScore<85，按掌握度升序取3）、buildCoachDefinition（写 topicPriorities）、recommendationText。mastery = avg/100 × 置信度因子（attempts<5 时 0.5+attempts/5，≥5 收敛）。
  - `quiz.ts` 加 pickPrioritized（薄弱主题先抽满再补齐）；`InterviewDefinition` 加 topicPriorities/mode。
  - `storage/learner.ts`（localStorage learner.v1，load 时校验兜底 emptyProfile）。
  - 结果页：delta vs 上次、强弱项聚合、AI 建议、按薄弱项继续训练；进度页：dashboard + 掌握度条 + 内联 SVG 折线 + 需要关注；面试页：30 分钟限时题组（追问 loop 待接）；设置页 = SettingsPanel（内联，替代 Modal）。
  - 删除 SetupPanel.tsx、SettingsModal.tsx（不向后兼容）。
- 记忆原则（ADR-015）：**结构化学习信号而非对话原文**——不把历史塞给 LLM，Coach 只看压缩画像；推荐逻辑当前为确定性规则（可测），后续可接 pi-agent-core 生成教练叙事。
- 测试：learner.test.ts 13 例（聚合/趋势/mastery 界/弱项推荐/会话映射/pickPrioritized），共 **46 例全过**；build 通过；dev 转译全 200。
- 坑：sessionFromQuiz 原签名带无用 answers 参数 → 按"删死代码"原则移除；recommendWeakTopics 需同时排除高均分（单次高分被置信度因子压低成弱项 → 误推荐），加 `avgScore<85` 条件。
