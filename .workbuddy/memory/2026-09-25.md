## 逐题反馈「收口轮」：3 个 P0 + Agent/Copilot 合并 runtime（ADR-084）

用户逐文件复查后指出 3 个 P0 + 1 个结构性问题，本轮全部改完。

### ★ 最重要的一条经验：runtime 状态与 UI 投影必须分开持有

三个 P0 全是同一个根因的不同表现——**把「UI 投影」当成了「运行时状态」**：

1. **standard 模式误弹反馈卡**：`afterEvaluation` 在 standard 下也会触发 `onEvaluation`
   （评分总得发生），而 UI 用 `feedback !== null` 推断「已暂停」。于是「评分完成 → 下一题交付」
   的窗口里（开放题下数秒）弹出反馈卡、题目只读、提交按钮消失。
   → 修正：运行时**显式下发** `awaitingFeedback` 参数，且**先置 `session.status` 再通知回调**
   （否则回调里读到的 status 还是旧的）。hook 另立 `awaitingFeedback` state 作暂停态真源。
   **注意**：用户建议的改法（在 `onEvaluation` 里读 `session.status`）本身是错的——
   当时 `afterEvaluation` 是先调回调、后置 status，读到的是 `'running'`。
2. **刷新后「让 Copilot 详细解释」消失**：只恢复了 `feedback`（投影），漏了 `lastEvaluation`
   （原始评分），而该入口条件是 `lastEvaluation` 非空。
3. **刷新后节奏 UI 错**：没把 `session.feedbackMode` 同步回 React state。

### 核心设计（下次改动前务必先读）

- **暂停点必须放在共享内部缝 `afterEvaluation()`**，不能放在 `evaluateAnswer` 工具里。
  判分有三条路径：`choiceAdvance`（选择题确定性 `gradeChoice`）、`fallbackAdvance`
  （`evaluateSessionQuestion`）、LLM 循环（`evaluateAnswer` 工具）。**只有第三条经过该工具**，
  塞进工具里会让选择题和降级路径静默地不暂停。三条路径现在都收敛到 `afterEvaluation()`。
- **不要用 `agent.abort()` 实现暂停**：运行时会按 `stopReason === 'aborted'` 归类为异常，
  打出 `model_error` 遥测 + 用户看到「模型返回错误」。正确做法是 `finishTurn` 钩子返回
  `{ action: 'end' }` 让模型停在正常轮次边界，并用 `beforeToolCall` 拦掉等待期的
  `getQuestion` / `evaluateAnswer`。已有测试锁住「暂停态 `errors` 为空」。
- **`evaluation === null` 不产生反馈**：否则「评分失败」会被投影成「0 分」，是伪造数据。
- `finishTurn` 返回 `undefined`（不是 `{ action: 'continue' }`）以保留默认调度，避免多一次 provider 请求。

### ★ 教训：断言必须**能失败**（本次抓到 1 个假通过用例）

`learner.test.ts` 原写 `expect(JSON.stringify(profile)).not.toContain(' 答案不正确，请参见解析')`
——**串首多了一个空格**，而 JSON 里数组元素没有前导空格，所以这条断言**永远为真**。
去掉空格后立刻变红：那个假 gap 确实进了 `profile`。

真因不在聚合层（`sessionFromQuiz` 已把选择题的 `gaps` 清空），而是**新加的 `evaluation` 字段**
原样留存了判分器原文——这是刻意的（历史回放要复用实时反馈卡）。
故正确的断言粒度是**只锁聚合信号**，而非整份 profile：

```ts
const profile = updateLearner(emptyProfile(), rec);
expect(JSON.stringify(profile.topicStats)).not.toContain('答案不正确，请参见解析');
expect(JSON.stringify(profile.misconceptionHits)).not.toContain('答案不正确，请参见解析');
```

推论：**「整份对象序列化后不含某串」是很差的断言**——它把「聚合结果」与「忠实原始记录」两种语义
混在一起，且极易被一个多余空格变成永真。要断言什么，就精确指到那个字段。
