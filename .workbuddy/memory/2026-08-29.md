### 为何 rag/agentic-ai 是"空转"——技术根因
`findQuestionForConcept`（`adaptive.ts:113`）硬依赖 `q.tests`：
```ts
const candidates = pool.filter((q) => (q.tests ?? []).some((t) => t.concept === conceptId));
if (candidates.length === 0) return null;
```
题没标 tests → 永远找不到题 → 返回 null。后果：
- 开 AI（useAI=true）→ 每步都触发 Dynamic Probe，让 LLM 现场生成临时题（慢、费、质量不可控）；

### 坑 1：`question:add` 的去重会剥掉所有符号，纯公式选项会被判重复
`selfharness-acceptance-rule-01` 四个选项原本是 `Δ_in^(j) ≥ 0 ∧ Δ_ho^(j) ≥ 0 ∧ max(...) > 0` 这类纯公式，被判「选项重复」。原因是 `normalizedText` 做 `NFKC + 小写 + replace(/[\p{P}\p{S}\s]+/gu,'')`，**≥ ∧ > × + 全被剥掉**，导致 B、C 归一化后变成同一串。
**修法**：把运算符写成中文（"大于等于/小于/等于/加/乘"），中文字符能保留，四选项即可区分。同时可读性也更好。

### 坑 2（已解决）：bias lint 要前置拦截，别等写完再返工
这次在写入脚本里内置了预判——`正确项最长 && max/min ≥ 1.8` 就打印告警。9 题全部无告警，`lint:bias` 实测**零命中**（仍为历史基线 8 条）。最终选项长度比 1.06×–1.34×。
**做法沉淀：写题脚本必须内置这个预判**，比写完再跑 lint 再改省一整轮。

### 工具缺陷：`question_audit.py` 的 VOLATILE_RE 含裸 `api`，噪声 64%
```python
VOLATILE_RE = re.compile(r"(?:aws|amazon|openai|anthropic|google|azure|api|sdk|...)", re.I)
```
`api` 会匹配到"API 调用限速""应用 API"这类**通用术语**。实测：87 条 missing-source 里 **56 条（64%）仅由通用 api 触发**，真正涉及厂商/认证/版本号的只有 31 条。
