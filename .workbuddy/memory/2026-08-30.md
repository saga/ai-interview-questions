# 2026-08-30

## 添加 Cloudflare Pages 发布支持
需求：能发布到 Cloudflare，且 python 与 offline 模型不发布。

### 结论与改动
- 应用是纯静态 SPA（Vite 构建到 `dist/`，`HashRouter` 走 URL hash → 无需 SPA fallback / Pages Functions）。
- 发布范围**结构性保证**只含 `dist/`：`wrangler pages deploy dist` 只上传该目录。
- 核实 `models/paraphrase-multilingual-MiniLM-L12-v2`（126MB ONNX）由 **Git LFS** 管理（`.gitattributes` 有 `*.onnx filter=lfs`），仅用于 `scripts/question_analysis.py` 的语义去重分析，**不参与浏览器构建** → 不能 gitignore，也自然不会被发布。`src/` 内无任何对 `models/`、`onnx`、`@xenova/transformers` 的引用（唯一 "models" 是 `pi-ai` 的 LLM provider API）。
- Python 工具链（`scripts/*.py`、`main.py`、`pyproject.toml`、`uv.lock`、`.venv`/`.hf-cache` 已 gitignore）同样不进 `dist/`。

### 新增/修改文件
- `wrangler.toml`（新建）：`name=ai-interview-trainer`、`pages_build_output_dir=dist`、`compatibility_date`；注释标明发布范围。
- `package.json`：加 `deploy` / `deploy:cloudflare` 脚本（`wrangler pages deploy dist`）+ devDependency `wrangler: ^4.0.0`。
- `.github/workflows/ci.yml`（新建，此前为空）：verify 任务（typecheck/test/validate/lint:bias/lint:length --changed/audit）+ 受 `secrets.CLOUDFLARE_API_TOKEN` 门控的 deploy 任务（仅 push 到 main 且有密钥时跑）。
- `README.md`：新增「部署到 Cloudflare Pages」小节（构建/发布命令、子路径 base 提示、Python 与 offline 模型不发布的说明）。

### 验证
- `wrangler.toml` 通过 tomllib 解析；`npm run build` 成功（1.75s，dist 3.8MB 最大 chunk < 25MB 限制）；`dist/` 仅 `assets/`+`index.html`，无 .py/.onnx；`lint:length` 仍 exit 0；`npm run deploy` 已接线。
- 未实测真实上传（需 Cloudflare 凭证）；用户 `npm install` 后 `npm run deploy` 或连 Git 仓库即可发布。

## 修复 npm ci 失败（lock 与 package.json 不同步）
CI 报 `EUSAGE`：`lock file's @earendil-works/pi-*@0.84.2 does not satisfy ^0.84.4`、Missing `wrangler@4.127.1` 等。
根因：`package.json` 被 `adddd` 等提交升级 pi-* 至 ^0.84.4 并新增 `wrangler ^4.0.0`，但 **package-lock.json 未同步提交**（仍 0.84.2、无 wrangler）。`npm ci` 要求 lock 与 package.json 严格一致，故失败。
修复：`npm install --package-lock-only` 重新生成 lock（含 pi-*@0.84.4、wrangler@4.127.1 及 cloudflare 传递依赖、protobufjs@7.6.6 等），`package.json` 未被改写。已本地 `npm ci` 验证通过（added 438 packages）。提交 `f68593b`（仅 package-lock.json）。

### 防复发纪律（多写手环境务必遵守）
- **任何改动 `package.json`（加依赖 / 升版本）的提交，必须同时提交重新生成的 `package-lock.json`**，否则 CI 的 `npm ci` 必红。
- 本地校验：`npm install --package-lock-only && npm ci --dry-run` 或先 `npm ci` 跑通再 push。
- 不要再出现「只 commit package.json 不 commit lock」的提交。
