## npm run test 失败修复（校招题库批次引入的过期断言）

- 根因 1：`campus-employment-company-2026-01/02/03.json` 新增 26 题 `cognitiveTask: "analyze"` 不在 schema 枚举内；题库在模块加载时整库 Zod 校验，单题失败导致 8 个 import 题库的 suite 在收集阶段全挂（617 个已执行测试全过）。修为 `infer`。
- 根因 2（被根因 1 遮蔽）：135 道新公司面经题缺 `knowledgeId`（数据契约），补全为 `topic`。
- 根因 3（被遮蔽）：`campusEmploymentCourse.test.ts` / `taxonomy.test.ts` 仍断言 500 题 / 375 单选，且依赖题干「多选」「长度 ≥80」——历史提交已移除这些标记。按用户要求不新增针对题目的测试，移除两条内容级断言并把数量同步到 635 题 / 510 单选。
- 教训：题库是 `import.meta.glob` eager + 模块加载即校验，任何新批次字段非法会让所有引用题库的测试**在收集阶段**失败，表层失败数远大于真实坏题数；排查先看 import 错误而非失败用例。
- `npm run validate:questions` 用独立 JSON 读取 + 自身规则，**不复用 questionSchema**，因此它绿并不能保证运行时题库合法；这是两个门禁的语义差异，别互相替代。
