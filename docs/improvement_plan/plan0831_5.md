我重新检查了当前 `main`。这版比上一版完整很多：`ConversationSession`、持久化、`end_interview`、本轮评价、history 排重都已经补上了。当前剩下的问题，主要集中在**“Interview mode 到底是不是 Agent mode”**以及状态一致性。

## P0：还有一个核心问题没真正解决

### 1. Chat 的 `interview mode` 仍然没有使用 `pi-agent-core`

这是现在最重要的一点。

`CopilotSidebar` 在：

```text
start_interview
continue_interview
```

时，进入的是：

```text
ConversationSession
   ↓
nextAdaptiveStep(...)
   ↓
askQuestion(...)
```

而不是：

```text
ConversationSession
   ↓
createInterviewAgent(...)
   ↓
pi-agent-core
   ↓
Agent decision loop
```

代码里虽然已经有独立的 `interviewCapability.ts`，但它本质仍是：

```text
buildSession()
nextAdaptiveStep()
evaluateAnswer()
```

并没有把 `InterviewAgent` 接进 Chat。

所以目前实际情况还是：

```text
Chat
 ├─ question mode → deterministic
 └─ interview mode → deterministic adaptive

独立 Agent Interview
 └─ pi-agent-core
```

也就是说，**“模式切换”完成了，但“runtime 切换”没有完成。**

这是我现在认为最值得继续跟进的唯一 P0。

## P0：两个 interview engine 仍然并存

现在存在：

```text
interviewEngine.nextAdaptiveStep()
```

以及：

```text
createInterviewAgent()
  └─ Agent + tools + fallback
```

前者被 Chat 使用，后者被 Agent Interview 使用。([GitHub][1])

这样以后必然出现：

> 在 Chat 里模拟面试，和在 Agent Interview 页面模拟面试，行为不完全一样。

我的建议非常明确：

```text
普通“给我出一道题”
→ Question capability

“开始模拟面试”
→ Interview capability
   → pi-agent-core
```

不要再让 Chat 自己实现一套“简化版 Agent 面试”。

---

## P1：`effectiveProfileFor()` 还没有被 Chat 真正使用

你已经解决了 Agent 的冻结 profile：

```text
历史 profile
+
本轮 evaluations
↓
effective profile
```

这个实现是正确方向。

但 Chat 的 adaptive continuation 这里还是：

```ts
nextAdaptiveStep(..., profile ?? emptyProfile(), ...)
```

而不是：

```ts
effectiveProfileFor(...)
```



所以：

```text
Agent Interview
✅ 感知本轮答题结果

Chat Interview
⚠️ 仍主要读取历史 profile
```

这应该一起修掉。

---

## P1：Chat 的 `ConversationSession` 和 `InterviewAgentSession` 仍然是两套状态模型

现在有：

```text
ConversationSession
 ├─ messages
 ├─ questions
 ├─ answers
 └─ evaluations
```

以及：

```text
InterviewAgentSession
 ├─ currentQuestion
 ├─ answers
 ├─ evaluations
 ├─ log
 └─ fallback state
```

([GitHub][2])

如果下一步真的把 Agent 接进 Chat，这两个状态最终一定要桥接。

最简单的方式不是强行合并，而是：

```text
ConversationSession
        │
        └── agentSession?: InterviewAgentSession
```

或者更好：

```text
ConversationSession
   ↓
InterviewAgentSession
   ↓
events → ConversationSession/UI
```

**不要再维护第三套状态。**

---

## P1：`turnCount` 语义现在不够准确

`addQuestionToSession()`：

```text
turnCount += 1
```

但它实际上代表的是：

> 出过几道题

不是：

> conversation turn 数

而 `context.turnCount` 也复用了这个字段。([GitHub][2])

以后用户：

```text
出题
→ 回答
→ 追问
→ 再回答
```

一个问题本身可能有多个 conversation turn。

建议改名为：

```text
questionCount
```

另外独立：

```text
messageTurnCount
```

不用复杂，但语义最好现在纠正。

## P1：`end_interview` 结束后仍然保留聊天消息，但 session 已经被清掉

这里：

```text
clearConversationSession()
setConvSession(null)
setConversationContext(initialConversationContext())
```

但：

```text
setMessages(...)
```

继续保留原聊天记录。

这会产生一个 UI 语义问题：

```text
屏幕上：
“刚结束 8 题面试”

内部：
已经没有 active session
```

用户紧接着输入：

> “下一题”

系统会把它当成新的 question session。

这其实不一定错，但 UI 最好明确“上一 session 已结束”，否则用户会认为自己还在原来的面试中。

## P1：Router 的“回答优先级”还是偏激进

当前：

```ts
if (
  context.pendingAction === 'answer' &&
  context.currentQuestionId
) {
  return answer_current_question;
}
```

也就是说，只要当前在答题状态：

> **任何用户输入都先当答案。** 

例如：

```text
“这题我不太会，换一道”
```

可能直接被当成答案，而不是：

```text
continue / skip
```

建议至少加入几个明确控制词：

```text
换一道
跳过
不想答
解释一下
提示一下
结束
```

这些应该优先于 `answer_current_question`。

---

## P1：Router Prompt 的 intent 列表和业务能力现在已经开始变多，建议补“状态约束”

目前 LLM classifier 知道：

```text
start
ask
answer
continue
end
evaluate
explain
chat
```



但真正重要的是：

> **什么状态下哪些 intent 合法。**

例如：

```text
没有 currentQuestion
→ answer_current_question 不合法

已经 answered
→ 再来的普通文本不能默认当 answer

已经 ended
→ continue 应创建新 session
```

这些不应该全部交给 prompt。

建议 router 输出后再加一层非常小的：

```text
validateIntentAgainstContext()
```

这是纯 deterministic rule，不需要 LLM。

---

## P2：ConversationSession 持久化最好加 Zod schema

目前：

```ts
JSON.parse(raw) as ConversationSession
```

是类型断言，不是运行时校验。([GitHub][2])

而 `conversationContext` 倒是有 schema。

这意味着损坏 / 老版本数据可能直接进入：

```text
questions
answers
evaluations
messages
```

建议加：

```text
conversationSessionSchema
```

然后：

```ts
conversationSessionSchema.safeParse(...)
```

顺便做版本迁移。

这对 localStorage 项目尤其值得做。

---

# 现在可以暂缓的事情

我不建议现在再继续增加：

```text
BKT
IRT
Bandit
Embedding reranker
多 Agent
复杂 memory
```

当前真正应该先收口的是：

```text
Chat
  ↓
Conversation Router
  ↓
Question Capability
  ↓
Interview Capability
       ↓
pi-agent-core
       ↓
shared Evaluation / Learner / Session
```

一旦这条链打通，整个项目的架构就基本成型。

## 我的建议顺序

**第一步：把 Chat 的 `interview` mode 真正接到现有 `createInterviewAgent()`。**

**第二步：让 Chat 和 Agent 共用同一个 interview session 状态，而不是两个平行状态。**

**第三步：补 Router 的 context validation + answer 优先级。**

**第四步：给 `ConversationSession` 加 Zod schema。**

做到这四步，我会认为这次 Chat/Agent 架构重构基本可以停止继续加结构，进入真实使用和数据验证阶段。

目前仓库 README 仍然把“模拟面试”和“Agent 面试”明确写成两个并存能力；从架构角度看，最终最好把它们描述成同一 Interview capability 的两种运行方式，而不是两个独立产品模块。([GitHub][3])
