可以。针对**现有题库**，我不建议“全部重写”，而是做一次 **curation / refactoring**：先自动筛选，再重点重写高价值问题，最后补少量缺口。

我看了当前仓库最新的题库相关 skill 和 audit 实现：现在已经有 `question:add`、`question:coverage`、`question:audit`、semantic analysis，以及 `article-to-questions / fill-coverage-gap / check-question-bank-quality`；但现有 audit 主要还是检查 schema、重复、题型、选项长度、topic/angle 和 coverage，还没有真正把“认知价值、答案确定性、选项粒度、诊断价值”作为现有题库清洗维度。

所以建议这样改。

# 一、不要重建题库，分成 4 类处理

把现有 1300+ 题分成：

```text
KEEP
  直接保留

REWRITE
  题目有价值，但题干/选项/答案设计需要改

MERGE / DELETE
  和已有题高度重复，或者知识增量太低

ADD
  真正缺失的重要题
```

目标不是：

```text
1317 → 再生成 1317
```

而是：

```text
1317
 ↓
质量筛选
 ↓
保留高价值题
 ↓
重写明显弱题
 ↓
删除冗余
 ↓
补真正缺口
```

---

# 二、第一步：先做一次“现有题库诊断”，不要立即改题

当前 `question_audit.py` 已经可以拿到：

* topic 数量
* angle 分布
* difficulty
* semantic duplicate
* option length
* coverage

这些继续使用即可。

但我建议额外得到下面几个维度：

```text
topic × angle × count
topic × difficulty
angle × difficulty
semantic cluster size
single/multiple ratio
```

尤其是：

```text
topic × angle × count
```

因为现在 skill 已经明确：

> 一个 topic × angle 超过 3 题，就属于“加深”而不是“补缺”。

所以先把题库分成：

```text
0       = gap
1       = sparse
2       = healthy
3       = deep
4+      = saturated
```

**不要看到 0 就自动补题，也不要看到 4+ 就自动删题。**

---

# 三、第二步：对现有题做“质量分层”

不要做一个伪精确的 `0~100 quality score`。

建议直接：

```text
A — KEEP
B — REVIEW
C — REWRITE
D — REMOVE
```

判断标准只用 6 个。

### 1. Knowledge Value

是不是值得 AI Engineer 掌握？

### 2. Cognitive Value

是在考：

```text
definition
mechanism
comparison
tradeoff
scenario
debugging
design
system-design
```

还是纯记忆？

### 3. Answer Determinism

有没有唯一稳定答案？

### 4. Distractor Quality

错误项是不是“差点正确”的真实误区？

### 5. Diagnostic Value

答错之后，是否知道考生具体缺什么？

### 6. Duplication

是不是和已有题只是换句话？

---

# 四、现有题最应该优先重写的类型

我建议先抓这 6 类。

## ① 纯 definition 题

例如：

```text
什么是 KV Cache？
什么是 RAG？
什么是 MCP？
什么是 GQA？
```

不是全部删除。

但如果一个 topic 已经有大量题：

```text
definition × 5
```

应该优先把其中 2～3 道改成：

```text
mechanism
comparison
tradeoff
scenario
debugging
```

你现在的 add-question skill 已经规定 easy 偏定义、medium 偏机制/比较、hard 偏计算/权衡/场景/系统设计。

---

## ② “下列哪项最准确”的伪单选题

这是现有题库非常值得查的一类。

例如：

```text
下列关于 RAG 的描述，哪一个最准确？
```

如果实际上有：

```text
A 对
B 也对
C 某种情况下也对
D 错
```

应该重写成：

```text
multiple
```

你现在的 skill 已经明确建议这种题改成多选，并要求批次 multiple ≥ 2/3。

---

## ③ 正确答案明显“最完整”

例如：

```text
A. 使用 vector search
B. 使用 hybrid search
C. 使用 hybrid search + reranker + query rewriting + cache + fallback
D. 不使用 retrieval
```

这种题即使长度检查通过，也不是真正好的 MCQ。

应重写成：

```text
A. vector-only retrieval
B. hybrid retrieval
C. lexical-only retrieval
D. graph-only retrieval
```

或者重新改题干，让每个选项都成为真正可比较的架构方案。

---

## ④ 错误选项太蠢

当前 skill 已经明确要求避免：

> 完全相反 / 明显荒谬 / 换模型 / 删测试 / 只看 token / 完全自动化

这类稻草人。

现有题库清洗时，这一类非常适合直接标：

```text
C — REWRITE
```

而不是只改一两个词。

---

## ⑤ 同一个 Concept 的题只是换句话

semantic analysis 现在已经有：

```text
fuzzy duplicate
semantic candidate
embedding cluster
```

而且当前本地 MiniLM 分析脚本已经支持语义候选和 clustering。

所以可以把：

```text
semantic cluster
   ↓
人工看 cluster 内的问题
   ↓
只保留认知任务真正不同的题
```

例如：

```text
KV Cache cluster

Q1 mechanism
Q2 mechanism
Q3 definition
Q4 tradeoff
Q5 debugging
```

真正有价值的是：

```text
Q1
Q4
Q5
```

而不是因为文本不相似就全部留下。

---

## ⑥ hard 但实际上不难

当前分析脚本已经有：

```text
difficulty predictability
```

它本身不是质量分数，而是用于判断 difficulty 是否可能存在 lexical cue / label leakage。

所以可以专门抓：

```text
hard
+
definition/fundamental
+
明显可以直接记忆回答
```

这些题优先降级：

```text
hard → medium
```

或者直接改成真正的 scenario / tradeoff / debugging。

---

# 五、现有题库不要强行添加 Concept 字段

这里我建议你特别谨慎。

你最新外部 Prompt 已经引入：

```text
knowledgeId
concepts
```

但当前仓库的覆盖设计仍然明确以：

```text
topic × angle
```

为主，而且 `fill-coverage-gap` 明确写了不要再引入额外概念层作为 coverage index。

因此：

**不要为了新 Prompt，把 1300 道旧题全部迁移成新的 `concepts` schema。**

更合理的是：

```text
KnowledgeNode
    ↓
topic
    ↓
Question
    ↓
angle
```

现阶段 Concept 作为：

```text
内容质量分析维度
```

而不是新的运行时主索引。

也就是说：

```text
Concept 可以由 analysis / review 推导
```

不一定需要写入 Question schema。

这样不会把当前已经稳定的题库架构重新复杂化。

# 七、然后不要逐题看 1300 道，而是按“风险优先级”处理

建议：

```text
P0

P1
重复 / 低诊断价值 / 错误项质量差 / 伪 hard
```

实际工作量会小很多。

# 八、重写时不要“重新生成整道题”，而是先给题一个目标

例如：

```text
Q123
当前：
topic = kv-cache
angle = definition
difficulty = easy

问题：
价值低 + 已有 4 道类似题

改造目标：
→ angle = tradeoff
→ difficulty = medium
→ 核心 Concept 不变
```

然后再让 LLM 重写。

而不是：

> 请重新生成一道 KV Cache 题。

后者非常容易又生成一个重复题。

# 九、对每一道 REWRITE，给 LLM 一个明确的“改题契约”

建议使用这种内部 Prompt：

```text
你正在维护一个已有的 AI/ML 面试题库。

下面是一道现有题目。

你的任务不是简单换句话说，而是：
在保留核心知识的前提下，提高它的面试价值和诊断价值。

必须：
1. 保留原题真正考察的核心知识。
2. 不得与已有题重复。
3. 如果原题是低价值 definition，优先转换为 mechanism / comparison / tradeoff / scenario / debugging。
4. 保证正确答案唯一。
5. 错误选项必须来自真实技术误解或条件错配。
6. 所有选项处于相同决策层级和粒度。
7. 不得通过答案长度、完整程度、专业术语数量泄露答案。
8. 不要为了增加难度而加入无关知识。
9. 保持题目 self-contained。
10. explanation 必须能说明核心原理和关键误区。

重点：
不要改变题目的核心 Knowledge；
优先改变 Cognitive Task。
```

这个 Prompt 比“生成新题”更适合存量题库改造。

# 十二、最终存量题库改造流程

我建议你现在直接采用：

```text
                现有题库
                   │
                   ▼
             question:audit
                   │
          ┌────────┼────────┐
          ▼        ▼        ▼
       重复风险   结构风险   分布风险
          │        │        │
          └────────┼────────┘
                   ▼
          semantic analysis
                   │
                   ▼
             Question clusters
                   │
                   ▼
          ┌──────────────────┐
          │ Content Review   │
          │                  │
          │ Value            │
          │ Cognitive Task   │
          │ Determinism      │
          │ Distractors      │
          │ Diagnostic       │
          └────────┬─────────┘
                   ▼
        ┌──────────┼──────────┐
        ▼          ▼          ▼
       KEEP     REWRITE     REMOVE
                    │
                    ▼
              Existing bank
                    │
                    ▼
              Coverage check
                    │
                    ▼
             Fill true gaps
```

### 最重要的原则

**先改旧题，再补新题。**

否则现在：

```text
旧题 1300
+
新生成 500
```

很容易变成：

```text
旧的重复题还在
+
新的重复题继续增加
```

最后只是题库越来越大。

更合理的是：

```text
1300
 ↓
自动审计
 ↓
删除/合并 100~200 个低价值或重复题
 ↓
重写 200~300 个边缘题
 ↓
保留 800~1000 个高价值题
 ↓
只补真正 P0/P1 缺口
```

**最终目标不是题多，而是每一个 `topic × angle` 里的题都有明显不同的认知价值。**

而当前仓库已经具备实现这套清洗流程的大部分基础设施；现在最大的缺口只是把现有 `audit + semantic analysis` 从“找异常”升级成“指导存量题目的 KEEP / REWRITE / REMOVE”。
