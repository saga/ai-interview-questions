我再次按当前 `main` 检查了这版，重点追了 **Chat → ConversationSession → pi-agent-core → Learner** 的完整生命周期。现在已经基本成型，但还有 **2 个 P0 + 3 个 P1**，建议先处理这些，不要继续加功能。

## P0

### 1. 刷新页面后，Chat Interview 会“假恢复”，但实际上已经失去 Agent

这是当前最大问题。

你现在把：

```text
ConversationSession
```

持久化了，但明确把：

```text
agentSession
```

排除在持久化之外。([raw.githubusercontent.com](https://raw.githubusercontent.com/saga/ai-interview-questions/main/src/application/conversation/conversationSession.ts))

同时 `CopilotSidebar` 初始化时：

```text
loadConversationSession()
  ↓
恢复 currentQuestion
  ↓
恢复 mode = interview
```

但：

```text
chatInterviewRef.current = null
```

不会恢复。

于是刷新后的状态实际上是：

```text
UI：
我还在 Interview

Context：
mode = interview

Agent：
不存在
```

最危险的是用户此时回答当前题：

```text
answer_current_question
```

代码发现：

```ts
convSession?.context.mode === 'interview'
&& chatInterviewRef.current
```

不成立，于是直接走下面的 **question mode 确定性评分路径**。([raw.githubusercontent.com](https://raw.githubusercontent.com/saga/ai-interview-questions/main/src/components/copilot/CopilotSidebar.tsx))

也就是：

> **刷新前是 Agent Interview，刷新后悄悄退化成普通 Question mode。**

这应该修。

### 推荐最简单方案

不要尝试序列化整个 `Agent`。

保存：

```text
ConversationSession
  + interview configuration
  + questionHistory
  + answers
  + evaluations
```

刷新后：

```text
load ConversationSession
       ↓
如果 mode === interview
       ↓
重新 createInterviewAgent()
       ↓
把已有 session state 恢复进去
       ↓
继续 agent
```

如果 `pi-agent-core` 本身不适合完整 hydrate，就应该显式把状态分成：

```text
Persistent Interview State
Runtime Agent State
```

然后重新构造 runtime。

现在注释已经说“刷新后由 Agent 侧重建”，但当前代码实际上**没有完成这个重建**。([raw.githubusercontent.com](https://raw.githubusercontent.com/saga/ai-interview-questions/main/src/application/conversation/conversationSession.ts))

### 2. `end_interview` 存在“clear 后又重新 save”的状态竞态

这里是一个真实 bug。

流程：

```ts
clearConversationSession();
setConvSession(null);
...
setMessages(...)
```

但后面的 callback 又：

```ts
if (convSession) {
  saveConversationSession({ ...convSession, messages: next });
}
```

([raw.githubusercontent.com](https://raw.githubusercontent.com/saga/ai-interview-questions/main/src/components/copilot/CopilotSidebar.tsx))

注意：

```text
clearConversationSession()
```

已经删掉了 localStorage。

但这个 callback 使用的是**旧闭包里的 `convSession`**，于是很可能：

```text
clear
 ↓
重新 save 旧 session
```

造成：

> 用户看到“已结束”，但刷新后又恢复了刚才那个 session。

这个要直接修掉。

结束流程应该严格是：

```text
build final SessionRecord
      ↓
persist learner/session record
      ↓
dispose Agent
      ↓
clear active ConversationSession
      ↓
set UI to ended state
```

**不要在 end 分支再调用任何 `saveConversationSession()`。**

# P1

### 3. `ConversationSession` 和 Agent Session 目前仍然存在“双向同步但没有单一真源”

现在 Chat 每次拿到 Agent 结果后都手工：

```text
controller.session
      ↓
复制
      ↓
ConversationSession
```

例如：

```ts
answers: { ...base.answers, ...controller.session.answers }
evaluations: { ...base.evaluations, ...controller.session.evaluations }
```

([raw.githubusercontent.com](https://raw.githubusercontent.com/saga/ai-interview-questions/main/src/components/copilot/CopilotSidebar.tsx))

这能工作，但长期容易产生：

```text
Agent session ≠ Conversation session
```

尤其以后加入：

* skip
* follow-up
* hint
* agent tool event
* partial evaluation

就会越来越麻烦。

建议最终明确：

```text
InterviewAgentSession = interview runtime source of truth
ConversationSession = persistence/UI projection
```

即：

```text
Agent event
   ↓
projectToConversationSession()
```

而不是在 `CopilotSidebar` 里手工拼对象。

---

### 4. `startChatInterview()` 的 Promise bridge 还存在“resolver 被覆盖”的潜在风险

现在：

```ts
resolver = res;
void agent.submitAnswer(...)
```

([raw.githubusercontent.com](https://raw.githubusercontent.com/saga/ai-interview-questions/main/src/application/conversation/interviewCapability.ts))

代码假定：

> 两次提交之间 Agent 一定空闲。

在当前 UI `loadingRef` 的保护下基本成立，但这是一个**隐含前提**。

以后如果：

```text
double click
keyboard submit
programmatic retry
event re-entry
```

同时发生：

```text
resolver A
resolver B
```

A 会丢。

建议 controller 内部显式：

```ts
busy: boolean
```

或者把 pending promise 做成单实例队列。

不用复杂，避免未来埋坑。

---

### 5. `questionCount` / `messageTurnCount` 现在仍有重复增加的风险

例如 Agent Interview 交付题目时：

```text
questionCount += 1
messageTurnCount += 1
```

([raw.githubusercontent.com](https://raw.githubusercontent.com/saga/ai-interview-questions/main/src/components/copilot/CopilotSidebar.tsx))

但是这些计数目前是在：

```text
ConversationSession
```

层维护，而 Agent runtime 自己还有：

```text
answers
evaluations
currentQuestion
log
```

以后 follow-up question / retry / hint 不一定是一道新题，但可能是一轮新的 Agent turn。

所以这里建议最终明确：

```text
questionCount = 题目数
messageTurnCount = 用户消息数
agentTurnCount = Agent decision loop 次数
```

现在先不用增加 `agentTurnCount`，但不要再把 `messageTurnCount` 当作 Agent turn 使用。

# 另外一个值得马上改的小问题

### `shouldUpgradeToInterview()` 已经几乎没有意义

现在：

```ts
return session.questionCount >= 2;
```

([raw.githubusercontent.com](https://raw.githubusercontent.com/saga/ai-interview-questions/main/src/application/conversation/conversationSession.ts))

实际上真正决定升级的是 `CopilotSidebar` 自己的：

```text
questionCount >= 2
&& continue
&& difficulty/topic 条件
```

([raw.githubusercontent.com](https://raw.githubusercontent.com/saga/ai-interview-questions/main/src/components/copilot/CopilotSidebar.tsx))

所以存在两个 upgrade policy。

建议只留一个。

我更建议：

```text
shouldUpgradeToInterview(intent, session)
```

统一放 router/application 层。

# 当前最重要的后续顺序

现在不要再大改架构了，按这个顺序收口：

```text
P0
① 修复 refresh 后 Agent session 无法恢复
② 修复 end_interview clear → save 竞态

P1
③ 明确 AgentSession 是 runtime source of truth
④ 给 ChatInterviewController 加 busy/并发保护
⑤ 收敛唯一的 upgrade policy
```

做完以后，我认为 **Chat / Question / Interview / Agent / Learner 这一层架构已经足够稳定，可以停止重构，开始做真实用户流程测试和题目质量测试**。
