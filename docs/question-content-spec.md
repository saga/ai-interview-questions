# 题目内容设计规范

**本文件是题库「内容质量」的唯一规范。** 回答的是**为什么**和**应该怎样**。

## 三层分工（不要混）

| 层 | 载体 | 回答的问题 | 谁能改 |
| --- | --- | --- | --- |
| **内容规范**（本文件） | `docs/question-content-spec.md` | 什么算一道好题？为什么这样要求？ | 人工修订，需 ADR |
| **数据契约** | `src/schemas/*.ts` + `scripts/validate-questions.ts`、`scripts/add-question.ts` | 数据**必须**是什么形状 | 代码，机器可执行 |
| **Workflow** | `skills/*/SKILL.md` | 什么时候做什么、跑哪些命令 | skill 自身 |

- **冲突时以数据契约为准**：契约是唯一裁决者，跑 `npm run validate:questions` 就知道。
  本规范描述的是契约**管不到**的部分（语义、认知层级、诊断价值）。
- **生成 Prompt 不是规范**：`docs/添加题库prompt.md` 是给 LLM 贴的生成指令
  （含 Canonical/Variant 流程、批量输出格式），它**引用**本规范，但不定义规范。
- **skill 不复制规则**：skill 只写 workflow，涉及内容要求时写「见 spec §N」。

> 契约能拦住的是：选项重复、答案越界、长度比 > 1.8×、`topic` 无节点。
> 契约**拦不住**的是：干扰项是稻草人、正确项因"更完整"胜出、多选题实际只考一个判断、
> 变体删掉了关键条件。**后者才是本规范存在的理由。**

---

## §1 Concept Scope —— 一个核心 Concept

每道题必须能一句话说清「这道题到底在测哪个核心 Concept」。

- 默认 **1 个 Core Concept + 0～2 个 Supporting / Prerequisite Concepts**。
- 仅 `comparison` / `tradeoff` / `design` / `system-design` 可要求多个独立 Concept。
- **去掉某 Concept 后题目仍然成立 ⇒ 该 Concept 不该进来。**

判据：答错之后能否定位到一个具体的知识缺口？大杂烩题诊断不出东西。

## §2 Answer Determinism —— 答案唯一可判定

正确答案必须由**题干约束 + 可靠技术事实**唯一确定。

- `single`：恰好一个正确，其余在给定条件下明确错误。
- `multiple`：每个正确项**独立成立**、每个干扰项**独立可排除**、答案集合唯一。正确项之间不得是同一事实的重复表述、上下位改写或因果链拆分；错误项之间也不得是同一误解的不同措辞。
- 不得依赖：未写出的前提、行业约定、模糊措辞、主观偏好、"也可能成立"。

> 多选题最常见的退化：几个正确项其实是同一个判断的不同说法
> （答对一题只需做一个判断）。`npm run question:quality` 的探测器 ④ 会标出这类嫌疑。

## §3 Self-contained —— 脱离来源可作答

考生默认**没有读过**任何来源文章、产品文档、Lens 或认证考纲。

- 禁止：`文中提到 / 根据本文 / 作者认为 / 前文所述 / 上述方法 / 该模型 / 这种方式`。
- 禁止「哪种做法符合某 Lens / 框架 / 考纲」这类问法——那考的是背诵，不是工程判断。
- 需要背景时：把作答所需的**最小 context 写进题干**，写成目标 + 约束 + 验收标准。

来源名称只放 `source` metadata，不进题干。

## §4 Evidence Boundary —— 不编造事实

正确答案依赖的核心技术事实必须可追溯。

- 禁止编造 benchmark、性能数字、产品行为、文章无依据的技术结论。
- 禁止用「文章外的重要事实」制造唯一答案。
- 允许补 context 使题目 self-contained（context enrichment），但不得新增一个决定正确答案的独立知识点（knowledge injection）；新增内容不得成为决定答案的关键未知事实。
- 涉及厂商 / API / 模型 / 认证的事实，必须在 `source` 里记核验日期；不确定就写条件句，不写绝对结论。

## §5 Option Design —— 同一决策层级、彼此独立

1. **同一决策层级**：所有选项处于相同抽象粒度、回答同一个问题、表达同一类判断。
2. **彼此独立**：每个选项独立可理解、表达一个主要判断，不引用「前者 / 后者 / 上述方案」。
3. **不靠"更完整"胜出**：难度应来自技术判断，不是信息量。

> 典型失败：正确项 A 是「是什么」、正确项 B 是「为什么」、正确项 C 是「反过来为什么不行」，
> 干扰项 D 是一整段反面论述。前三项不在同一认知层级，等于让考生从同一段解析里拆三句话。
> `npm run question:quality` 的探测器 ① 会标出这类嫌疑。

## §6 Wrong Options —— 干扰项必须"差点就对"

干扰项来自**真实技术误解或工程误判**，优先这几类：

- 混淆相邻概念；遗漏必要条件；把充分条件当必要条件；
- 忽略 trade-off / 系统瓶颈；把局部优化当系统优化；把理论最优当工程最优；
- 将训练结论错误迁移到推理、将 benchmark 结论错误迁移到生产；
- 忽略状态、一致性、成本、可靠性或安全。

**禁止稻草人选项**：完全相反、明显荒谬、"换模型 / 删测试 / 只看 token / 完全自动化"——
它们让题目退化成不用读题就能排除。

自检：遮住正确答案后，剩余选项能否让懂行的人**犹豫 2 秒以上**？

## §7 Option Balance & Answer Leakage —— 不能从形式猜出答案

不得通过以下形式泄露答案：**长度、专业术语数量、限定词、语气、绝对化程度、信息完整程度、选项结构**
（除非这些本身就是考察内容）。

三个层次，逐层加严：

| 层次 | 判据 | 谁拦 |
| --- | --- | --- |
| 长度失衡 | 最长/最短 > 1.8× 且正确项全局最长 | `npm run lint:bias`（硬门禁，导入即拦） |
| 信息密度泄题 | 正确项**均长**/均专业度显著高于干扰项 | `npm run question:quality` 探测器 ③（软信号） |
| 语义泄题 | 题干/选项出现只对正确项成立的限定词（唯一 / 总是 / 必须同时） | 人工 + LLM challenger |

> **长度平衡 ≠ 选项质量平衡。** 前两项都通过的题，仍然可能干扰项是稻草人
> （见 §6）或多选题只考一个判断（见 §2）。

## §8 Variant 知识一致性 —— 什么能改、什么不能改

**Variant = 同一 assessment contract 的表达 / 情境变体。**

**能改**（表达层）：场景（等价替换，不得增加推理步骤/背景负担/决策变量）、提问方式、framing、选项措辞。
**不能改**（考察内容层，一律由程序从 canonical 继承）：Core Concept、核心技术事实、
正确答案逻辑、`angle`、`cognitiveTask`、`difficulty`、required concepts、诊断目标、正确推理路径。

> 换 `angle` 或 `cognitiveTask` **不是变体的职责** —— 那要新建一道 canonical，
> 它再生成自己的变体池。理由见下：变体继承 canonical 的 `topic × angle` 且不参与覆盖率，
> 用变体换 angle 等于声称换了考察维度、数据里却没换。
>
> 生成指令（含正反例与改写幅度口径）见 `docs/添加题库prompt.md` §2 / §19；
> 本规范只定「什么能改」的边界，不重复流程。

- 不得为生成变体引入新的独立核心知识。若回答变体需要额外掌握一个新 Concept，
  **它应该是新题，不是变体**。
- 变体的 `topic / angle / difficulty / answer 索引 / explanation` 由程序从 canonical 继承
  （`src/ai/variant.ts`），LLM 只改表达。

> **变体不是补覆盖缺口的主要机制。** 变体继承 canonical 的 `topic × angle`，
> 用它补洞等于把 A 格的题搬到 B 格——A 格重新空出来，**覆盖率永远补不满**。
> 变体的正确用途是**同格内扩充题量**（减少重复感），补缺口要靠 curate/rewrite 或新写 canonical。

变体落盘前必须过超采 + 五维质询（`scripts/question-variants.ts --oversample`、
`src/ai/variantChallenger.ts`）。结构校验（`validateVariant`）只是**漂移探测器**，
不是语义等价性证明。

## §9 题型分布 —— 以多选题为主

- 一批新题中 **multiple ≥ 2/3**（`scripts/add-question.ts` 硬门禁：本批 ≥3 道选择题且单选 > 1/3 直接报错）。
- `single` 只用于结论唯一、无法拆成多个独立判断的情形：定义判定、单值计算、唯一根因定位。
- 「下列哪项描述最准确」这类把多个独立判断压成最优选项的单选题，**应改写为多选**。

## 与自动化工具的关系

| 工具 | 覆盖本规范哪些条 | 性质 |
| --- | --- | --- |
| `npm run validate:questions` | 契约层（§2 的索引合法性、§9 的结构前提） | 硬门禁 |
| `npm run question:add --check` | §9 题型分布、§7 长度硬阈值、选项重复 | 硬门禁 |
| `npm run lint:bias` | §7 长度失衡 | 回归探针（不阻断） |
| `npm run question:quality` | §2 多判断退化、§5 层级混杂、§7 信息密度 | **软信号，非门禁** |
| LLM challenger / 人工 | §1、§3、§4、§6 | 不可自动化 |

`question:quality` 的四类嫌疑是**词汇/统计信号**，命中 = 值得复核，**不等于必须改写**。
不因为这些信号新增 lint 硬门禁。
