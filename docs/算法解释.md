# AI Interview Trainer 算法说明

本文说明自适应训练器中各类算法的职责、适用边界和推荐落地顺序。重点不是完整推导，而是帮助判断：

- 用户是否掌握某个知识点？
- 题目有多难、区分度有多高？
- 下一道题应该考什么？
- 一组题如何保持相关但不重复？
- 知识点之间如何确定学习顺序？

## 整体体系

这些算法属于不同层次，不应混在一起理解：

```text
Question Bank
     |
     +-- Question difficulty / Concept graph / Angle coverage
     |
     +-- User answer
             |
             v
       Learner model
       BKT / DKT: 用户会不会？
       IRT: 题目多难？
             |
             v
       Candidate ranking
       Rules / Bandit: 下一题选什么？
```

文本算法位于题库处理侧：

```text
TF-IDF / Embedding / MMR
    |
    +-- 检索相似题
    +-- 发现重复题
    +-- 组合相关且多样的题目
```

图算法位于知识组织侧：

```text
Graph / DAG
    |
    +-- 前置知识
    +-- 学习顺序
    +-- 知识邻域与重要性
```

## 学习者建模：BKT 与 DKT

### BKT：Bayesian Knowledge Tracing

#### 解决的问题

BKT 估计用户真正掌握某个知识点的概率，而不是简单计算答题平均分。

例如用户依次答题：

```text
Q1 错误，Q2 正确，Q3 错误，Q4 正确
```

平均分只能得到 50%。BKT 还会考虑用户可能已经掌握但偶尔粗心，或者原本不会、在练习中逐渐学会。

#### 核心参数

| 参数 | 含义 |
| --- | --- |
| `P(L0)` | 初始掌握概率 |
| `P(T)` | 做题后学会的概率 |
| `P(G)` | 不掌握时猜对的概率 |
| `P(S)` | 掌握后粗心答错的概率 |

每次答题都会经历：

```text
Answer observation
        |
        v
Bayesian update
        |
        v
Knowledge mastery
```

#### 在本项目中的用法

可以按 `concept × angle` 维护掌握度，例如：

```text
Transformer / mechanism       0.91
Transformer / tradeoff        0.38
Transformer / application     0.67
```

下一次训练优先选择低掌握度、但具有明确前置关系的知识点。

#### 局限

经典 BKT 将知识点简化为“掌握 / 未掌握”，难以表达架构理解、实现能力和权衡判断之间的差异。项目中的 `Concept × Angle` 可以缓解这一问题。

### DKT：Deep Knowledge Tracing

DKT 用 RNN、LSTM 或 Transformer 从大量答题历史中预测用户下一题答对的概率。它可以学习知识迁移、错误模式和遗忘等复杂关系。

但 DKT 很依赖数据量。当前项目以单用户、local-first 训练为主，优先使用规则或 BKT 更实际：

```text
现在：Deterministic rules / BKT
未来：BKT + IRT
数据足够后：DKT
```

## 题目与能力估计：IRT

### IRT：Item Response Theory

IRT 关注两个问题：

- 用户能力有多高？
- 题目难度和区分度有多大？

同样一次答对，答对基础定义题和答对高难度权衡题，提供的能力证据并不相同。

### 1PL / Rasch 模型

最简单的 1PL 模型只考虑题目难度：

$$
P(correct)=\frac{1}{1+e^{-(\theta-b)}}
$$

其中：

- `θ`：用户能力
- `b`：题目难度

如果用户能力为 `1.0`，题目难度为 `2.0`，答对这道题就是较强的能力证据。

### 2PL 与 3PL

| 模型 | 增加的因素 | 含义 |
| --- | --- | --- |
| 1PL | 难度 `b` | 题目有多难 |
| 2PL | 区分度 `a` | 题目区分高手和普通人的能力 |
| 3PL | 猜测 `c` | 不会时猜对的概率 |

选择题可以考虑猜测参数，但多选题不能简单套用四选一的 `0.25`，需要单独建模。

### 在题库中的落点

题库当前的：

```json
{ "difficulty": "hard" }
```

表示作者声明的难度。积累真实答题数据后，可以补充观测值：

```json
{
  "declaredDifficulty": "hard",
  "observed": {
    "difficulty": 1.42,
    "discrimination": 1.73,
    "sampleSize": 183
  }
}
```

### BKT 与 IRT 的配合

两者职责互补：

```text
IRT -> 题目难度、区分度
BKT -> 用户掌握度
       |
       v
选择适合当前能力、信息价值更高的题目
```

## 选题策略：Bandit

### Bandit 是什么？

Multi-Armed Bandit 将每个候选知识点或题目视为一个动作，通过反馈学习“下一步选哪个动作最值得”。反馈可以包括掌握度提升、覆盖新角度、答题质量或用户完成率。

### Exploration 与 Exploitation

| 策略 | 行为 |
| --- | --- |
| Exploitation | 继续练习已知的薄弱点 |
| Exploration | 偶尔探索掌握度未知的新知识点 |

两者的平衡适合自适应面试，但当前项目已有 `Concept × Angle`、前置关系、难度和新鲜度等信号，确定性排序已经足够实用。

### Contextual Bandit

Contextual Bandit 会把用户画像、近期答案、知识点、角度、题目难度和会话状态作为上下文，再选择题目。它比普通 Bandit 更贴近本项目，但应在有稳定反馈数据后再引入。

## 检索与去重：MMR、TF-IDF 与 Embedding

### MMR：Maximal Marginal Relevance

MMR 用来从候选题中选择一组“既相关又不重复”的题。其目标是在相关性和多样性之间平衡：

$$
MMR(d)=\lambda\,Similarity(query,d)
-(1-\lambda)\,Similarity(d,selected)
$$

因此，5 道 Transformer 题可以分别覆盖定义、机制、复杂度、比较和权衡，而不是换词重复问 self-attention。

适用场景：题目生成、组卷、课程覆盖和候选题去重。

### TF-IDF

TF-IDF 衡量词语对一篇文本的区分度：

- TF：词在当前文本中的频率
- IDF：词在全部文本中有多罕见

它是轻量、可解释的 baseline，适合关键词检索和初步去重，不需要调用 LLM。

### Embedding Similarity

将题目编码为向量，再用余弦相似度衡量语义接近程度：

```text
Question A -> vector A
Question B -> vector B
cosine(vector A, vector B) -> similarity
```

适合重复检测、相似题检索、知识匹配、证据检索和必答要点匹配。

需要明确：

> embedding similarity 表示“像不像”，不表示“对不对”。

## 知识图谱：DAG 与 PageRank

### Graph / DAG

知识图可以表示前置关系：

```text
Linear Algebra -> Probability -> Neural Network
                                  |
                                  v
                              Attention -> Transformer
```

### Topological Sort

对无环前置图进行拓扑排序，可以得到满足前置约束的学习顺序。它适合生成课程路径和安排训练主题。

### Prerequisite Closure

用户选择 Transformer 时，可以递归展开所有前置知识：

```text
Linear Algebra -> Attention -> Transformer
```

这通常比直接按重要性排序更适合作为学习路径的基础。

### PageRank

PageRank 根据节点被其他重要节点指向的程度估计相对重要性。它可以发现知识图中的中心节点，但知识依赖关系不等于网页链接关系，因此当前不应把 PageRank 当作核心选题依据。

## 算法职责总览

| 算法 | 主要解决的问题 |
| --- | --- |
| BKT | 用户是否掌握知识点 |
| DKT | 从大量历史中学习掌握模式 |
| IRT | 题目难度、区分度和用户能力 |
| Bandit | 下一步选择哪个动作 |
| MMR | 选择相关但不重复的一组题 |
| TF-IDF | 传统文本检索与词项相似度 |
| Embedding | 语义相似度与向量检索 |
| Topological Sort | 满足前置关系的学习顺序 |
| Graph Traversal | 查找前置、后续和邻近知识 |
| PageRank | 图中的相对重要性 |
| Clustering | 自动发现题目或知识分组 |
| Cosine Similarity | 衡量两个向量的接近程度 |

## 在本项目中的落地路线

### 当前阶段

优先组合：

```text
Concept × Angle
    + Prerequisite DAG
    + Deterministic ranking
    + Embedding similarity
    + MMR
```

这套组合已经能支持薄弱项优先、前置知识约束、语义去重和角度覆盖。

### 有真实用户数据后

引入 BKT 估计掌握度，再用 IRT 估计题目难度与区分度：

```text
BKT -> mastery
IRT -> difficulty / discrimination
```

### 数据规模更大后

再考虑 Contextual Bandit 优化下一题选择。只有积累了稳定的用户、题目、知识点、角度、答案、评分和时间戳数据后，DKT 才值得评估。

## 推荐的系统形态

项目可以把“算法决策”和“自然语言交互”分开：

```text
Algorithmic intelligence
    |
    +-- 决定考什么、为什么考
    |
    v
pi-agent-core
    |
    +-- 决定怎么问、是否追问、何时收尾
    |
    v
LLM
    |
    +-- 生成自然的面试表达
```

这样，算法负责可解释、可测试的选题和评分依据，Agent 负责把决定转换成自然的面试交互。
