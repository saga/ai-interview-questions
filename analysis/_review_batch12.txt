• rlhf-goodhart-01  [hard]  concepts=
   Q: 在 LLM 的偏好对齐（RLHF 或 DPO）过程中，经常观察到随着对偏好信号优化强度的增加，模型在代理奖励（Proxy Reward）上的得分不断攀升，但人类评估的实际真实质量却在达到峰值后开始下降。关于这种“奖励过优化”（Reward Overoptimization）现象，以下哪些选项是正确的？（多选）
     0 ✓ 该现象符合古德哈特定律（Goodhart's Law），即当一个代理指标（Proxy Metric）被用作直接优化目标时，它就会失去作为有效测量指标的资格
     1 ✓ 无论是显式训练的奖励模型还是隐式嵌入的偏好目标，本质上都是真实人类偏好的近似代理（Proxy），过度优化会迫使模型利用代理模型的缺陷与漏洞
     2 ✓ 奖励过优化的常见典型表现包括字数冗长偏好（Verbosity Bias）以及对用户立场的谄媚（Sycophancy）
     3   该现象是 PPO 强化学习算法特有的缺陷，采用 DPO 算法训练可以彻底避免奖励过优化
   A: 符合Goodhart、代理近似易被利用、表现冗长谄媚、DPO亦会过优化。

• rlvr-pref-01  [medium]  concepts=
   Q: 在 LLM 的对齐与推理能力训练实践中，针对不同任务类型存在“偏好学习”（Preference Learning，如 RLHF/DPO）与“可验证奖励”（Verifiable Rewards，如 RLVR/GRPO）两条技术路径。关于这两条路径的适用边界与选型逻辑，以下说法正确的是哪一项？
     0   可验证奖励可以通过代码测试用例或数学规则提供精确反馈，因此能完全替代偏好学习并应用于所有 LLM 任务场景
     1 ✓ 对于结果可由程序/规则客观校验的任务（如代码 Pass/Fail、数学题最终答案），应优先采用可验证奖励；对于涉及同理心、语气、安全性和主观偏好的开放式任务，仍需依赖偏好学习
     2   偏好学习在数学和代码推理任务上的上限远高于可验证奖励，因为人类标注员能更好地评估解题思路的优雅度，机器规则只关注最终对错而忽略过程价值
     3   可验证奖励只能用于监督微调（SFT）阶段，不能结合强化学习（RL）算法使用，因为可验证信号必须来自静态标注，无法在在线策略的奖励塑形中被动态利用，且 RL 阶段只能接受偏好类或环境类奖励
   A: 可验证奖励以程序/规则客观校验代码数学，偏好学习管主观开放任务；二者互补非替代。
