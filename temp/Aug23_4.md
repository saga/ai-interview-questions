我想添加一个 “个人目的”页面，相关作为系统性提示词，给整个面试做一个方向指导，比如“我是谁” / “我的目的” / “我的经验” / “希望增强的部分” 等等，这个该如何设计？

---------

可以，而且我认为这个页面**非常值得加**。但不要把它设计成“用户资料页”，而应该设计成一个很轻量的 **Interview Goal / Personal Context**。

核心目的只有一个：

> **告诉 AI：这次面试是为“什么样的我”服务的。**

这样它就可以作为整个训练过程的**系统级上下文**，影响出题、评分、推荐和反馈。

## 1. 页面不要做复杂

我建议页面就 4 个核心问题：

### 我是谁

例如：

> 我是一名有 5 年后端开发经验的工程师，目前主要使用 Python / Java，最近开始转向 AI Engineering。

### 我的目的

例如：

> 准备 AI Engineer / AI Application Engineer 面试，希望系统补齐 LLM 和 Agent Engineering 知识。

### 我的经验

例如：

> 做过 RAG、LLM API 集成和一些 LangChain 项目，但没有真正设计过生产级 Agent 系统。

### 我希望增强什么

例如：

> 希望重点提升 Agent 架构设计、RAG、LLM Evaluation、系统设计和工程 Trade-off。

---

## 2. 数据结构不要复杂

直接一个 `LearnerProfile` 外挂一个 `PersonalContext`：

```ts
interface PersonalContext {
  identity: string
  goal: string
  experience: string
  focusAreas: string[]
}
```

例如：

```json
{
  "identity": "后端工程师，5 年经验，主要使用 Python 和 Java",
  "goal": "准备 AI Engineer 面试",
  "experience": "做过 RAG 和 LLM API 集成，但缺少生产级 Agent 系统经验",
  "focusAreas": [
    "Agent Architecture",
    "RAG",
    "LLM Evaluation",
    "System Design"
  ]
}
```

**我不会现在加入职业、公司、学历、地点、薪资之类字段。**

这些不是这个产品当前需要的信息。

---

# 3. 它和 Learner Memory 要明确区分

这是这个设计里最重要的一点。

你现在已经有：

```text
Learner Memory
```

它回答的是：

> **“系统观察到你现在会什么 / 不会什么。”**

Personal Context 回答的是：

> **“你希望自己成为什么 / 为什么训练。”**

所以：

```text
Personal Context
    ↓
用户主动告诉系统
    ↓
训练方向


Learner Memory
    ↓
系统从训练中观察
    ↓
实际能力
```

例如用户说：

```text
希望重点学习 Agent Architecture
```

但连续 5 次 Agent Architecture 都拿 90 分。

那么系统应该：

```text
Personal Goal
    Agent Architecture ↑

Learner Memory
    Agent Architecture mastery = 0.92
```

最后推荐：

> 你已经具备较好的 Agent Architecture 基础，建议开始转向 Agent Reliability / Evaluation。

这就比单纯根据用户填写的目标推荐好很多。

---

# 4. 它应该如何进入 LLM？

我不建议把整个页面原文直接拼到每一个 prompt 里。

增加一个很简单的：

```ts
buildPersonalContextPrompt()
```

例如最终形成：

```text
## Candidate Context

Identity:
Backend engineer with 5 years of experience...

Goal:
Prepare for AI Engineer interviews...

Experience:
Has experience with RAG and LLM API integration...

Focus:
Agent Architecture, RAG, LLM Evaluation, System Design
```

然后：

```text
System Prompt
    +
Personal Context
    +
Canonical Question
    ↓
LLM
```

---

# 5. 但不是所有 LLM 调用都应该使用它

这是我认为特别重要的地方。

### 变体生成

可以使用：

```text
Personal Context ✓
```

因为：

> “把这道题改写成更符合我的背景的问题。”

例如用户是 Java 后端工程师：

```text
普通：
如何设计一个 Agent？

个性化：
假设你负责一个 Java 微服务平台，需要加入 Agent 能力，你会如何设计...
```

---

### 开放题评分

**可以使用，但作用要很克制。**

例如：

```text
用户背景：
有后端经验，但 AI 工程经验较少
```

用户回答：

> 我会使用 Redis、Kafka 和 Kubernetes……

AI 不应该因为：

> “这个人 AI 经验少”

就降低 correctness。

所以 Personal Context 不能改变**客观评分标准**。

应该影响的是：

```text
feedback
recommendation
communication
```

而不是：

```text
correctness
```

例如：

> 你的系统设计基础较好，但回答中对 Agent evaluation 的讨论较少。考虑到你的目标是 AI Engineer，可以重点补充这一部分。

这就非常合理。

---

# 6. 更重要的是影响“出题”

这其实是这个功能最大的价值。

你现在：

```text
Learner Memory
      ↓
recommendWeakTopics()
      ↓
topicPriorities
```

可以变成：

```text
Personal Context
      +
Learner Memory
      ↓
Training Direction
      ↓
topicPriorities
```

但这里**不要引入新的复杂推荐算法**。

简单规则就够：

```text
Personal Focus
    ↓
优先级 +1

Weak Topic
    ↓
优先级 +1

Prerequisite
    ↓
必要时补充

Already Mastered
    ↓
降低优先级
```

例如：

```text
用户目标：
Agent Engineering

用户薄弱：
Evaluation
Tool Calling

用户已经掌握：
Transformer
RAG basics
```

下一轮：

```text
Agent Evaluation
Tool Calling
Agent Architecture
```

而不是继续出 Transformer 基础题。

# 7. UI 我建议非常简单

不要做成一张很“企业系统”的 Profile Form。

可以叫：

## 🎯 我的面试目标

> 告诉教练你是谁、为什么准备这次面试，以及希望重点提升什么。

然后：

```text
┌─────────────────────────────────────┐
│ 我是谁                              │
│                                     │
│ [ 后端工程师，5年经验，目前转向AI ] │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 我的目的                            │
│                                     │
│ [ 准备 AI Engineer 面试             │
│   希望进入 AI Engineering 方向 ]    │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 我的经验                            │
│                                     │
│ [ 做过 RAG、LLM API 集成…… ]        │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 我希望增强                           │
│                                     │
│ [ Agent Architecture ]              │
│ [ LLM Evaluation ]                  │
│ [ System Design ]                   │
│                                     │
│ + 添加                              │
└─────────────────────────────────────┘

                 [ 保存 ]
```

甚至可以加一个：

> **让 AI 帮我整理**

用户输入一段自然语言：

> 我是做后端的，最近开始做 AI，想找 AI Engineer 工作，但是 Agent 方面比较弱……

然后 LLM 只负责把它整理成：

```json
{
  "identity": "...",
  "goal": "...",
  "experience": "...",
  "focusAreas": [...]
}
```

这属于非常合适的 one-shot LLM 用法。

# 8. 我会把它放在现有架构这里

不用增加新层：

```text
storage/
  settings.ts
  learner.ts
  personalContext.ts       ← 新增

domain/
  learner.ts
  ...
  personalContext.ts       ← 可选，纯类型/格式化逻辑

application/
  interviewEngine.ts
```

然后：

```text
PersonalContext
       │
       ├──────────────┐
       ↓              ↓
Learner Memory    LLM Context
       │              │
       ↓              ↓
Recommendation    Variant / Evaluation
       │
       ↓
InterviewDefinition
```

### 我甚至不建议叫 `systemPrompt`

数据应该叫：

```ts
PersonalContext
```

而不是：

```ts
SystemPrompt
```

因为用户填写的是**个人背景与目标**，不是 prompt。

最后由代码：

```ts
buildLLMContext(personalContext)
```

把它转换成 prompt。

这样以后你修改 prompt 格式，不需要迁移用户数据。

---

## 最终我建议就保持这个规模

```text
Personal Context
├── identity
├── goal
├── experience
└── focusAreas[]
```

然后它影响三个地方：

```text
             Personal Context
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
     出题          评分          推荐
   个性化题干    个性化反馈      训练方向
```

而 **Learner Memory 负责“实际能力”**。

这两个东西组合起来，你的产品就形成了一个很漂亮的闭环：

```text
我是谁 / 我要去哪
        ↓
Personal Context
        ↓
    训练与面试
        ↓
    实际表现
        ↓
  Learner Memory
        ↓
我应该下一步练什么
        ↓
    下一轮训练
```

我认为这比继续给 `questions.json` 增加更多字段，对产品价值的提升要大得多，而且**不需要引入任何新的复杂架构**。
