## 任务四：按用户建议复核并更正两份架构分析文档（纯文档改动，代码零改动）

用户的核心判断：**「选择题完全跳过 Agent 决策」是把 Agent 决策能力与 LLM 调用绑太紧了**。给的验收标准只有一条——
> 选择题答完以后，下一题是不是根据当前 learner state 做了 adaptive decision？

### 核实结果：答案是「是」，原判定为误报

逐跳跟读确认的调用链：

```
choiceAdvance()               interviewAgent.ts:212
  ├─ evaluateSessionQuestion()  → gradeChoice（确定性判分）
  └─ fallbackNextQuestion()     interviewAgent.ts:160
       ├─ pool    = 传入 Agent 的 bank（已排除 disabledCategories）− 已问题
       ├─ signals = 从 session.evaluations 实时重建（topic/score/difficulty）
       └─ pickNextAdaptive(pool, signals, profile, Math.random)   adaptive.ts:114
```

`pickNextAdaptive` 是真自适应：上一题得分 → `decideStrategy`（<60 gap-probe / ≥80 broaden / 否则 deep-dive）、难度升降、`relatedOf`、`prerequisiteClosure`、`recommendWeakTopics(profile)`，以及每个策略子集内按 (topic, angle) 掌握度细选（`angleWeakRank` + `angleEvidence`）。**不是「取下一道未问题」**。

**一个必须精确说明的边界**：`profile`（跨会话 mastery/angleCoverage）在会话进行中是**会话开始时的快照**，只在会话结束时经 `finalize → onComplete → handleAgentComplete → updateLearner → saveLearner` 落库。**两条路径完全一致**（`useTrainingSession.ts:216/265` 同样只在会话结束调用），所以不是缺陷也不构成双引擎分叉。中途一度以为 Agent 路径根本不落库，追到 `useAgentInterview.ts:148 finalize()` 才发现是经 App.tsx 传下来的 `onComplete` 回调。

### 顺带发现我自己的报告 A1 有一行是错的

`深度审查报告.md` A1 原表写「categories/difficulties/disabledCategories 过滤：确定性引擎应用、Agent 兜底**不应用**」，结论是「Agent 兜底绕过用户设置的分类与难度约束」。核实后**不成立**：
- `disabledCategories` 两边都应用 —— Agent 侧在 `useAgentInterview.ts:193` 和 `:358` 就把 bank 预过滤了。
- `def.categories` / `def.difficulties` 来自 `session.definition`（训练/组卷定义），而 Agent 会话类型是 `InterviewAgentSession`，**根本没这一层**。不是"绕过"，是"该维度不存在"。
- rng 也非差异（`pickNextAdaptive` 默认参数就是 `Math.random`）。

→ A1 由 **P0 降级为 P2**，只剩「pool 组装写了两遍」这个可维护性问题。真实差异仅剩「题数上限来源」和「确定性路径不调 `finalizeQuestion` 所以不出变体」，两者都按设计。

- `ARCHITECTURE-REVIEW.md`：第 4 条改写为「✅ 已复核关闭」，补调用链 + 自适应输入表 + 明确不建议塞 LLM；P0 清单两项标为已修复；§四总结同步；末尾加复核记录。

## 任务五：`OPENING_INSTRUCTION` 可配置化（ARCHITECTURE-REVIEW 第 5 条，ADR-051）

### 做法（选了 `config.prompts.agentOpening`，不是 `createInterviewAgent` 参数）

理由：本条诉求是「**用户**能通过设置页修改」；做成构造参数只解决代码侧可注入性，用户照样改不了。

1. `schemas/ai-config.ts` 的 `promptConfigSchema` 加 `agentOpening: z.string().optional()`。
   设置页 Monaco 借已有的 `z.toJSONSchema(aiConfigSchema)` **自动获得校验与补全**，零额外接线。
2. 默认值从 `useAgentInterview.ts` 模块常量**上移到 `agent/prompt.ts`**
   （`INTERVIEW_AGENT_OPENING_INSTRUCTION`），与 `INTERVIEW_AGENT_SYSTEM_PROMPT` 同处。
   关键原因：设置页「恢复默认值」按钮要引用它，留在 hooks 层会让组件反向依赖 hooks 内部常量。
3. 回退逻辑抽成纯函数 `resolveOpeningInstruction(agentOpening)` 放 `agent/prompt.ts`：
   `undefined` 与**空白串**都回退默认。抽函数是因为 hooks 层无测试基建，而「用户清空输入框不能发空指令」这条必须可测。
4. 设置页加编辑区，说明里写明题数硬上限由 `MAX_AGENT_QUESTIONS` 控制（这里是软目标）。
5. `storage/settings.ts` 的 `safeConfigSnapshot` 同步加 `agentOpening`（审计日志只记 present/length）。

`interviewAgent.ts` **未改** —— `handle.start(instruction)` 本来就接受指令参数。

→ 意识到这两个不是本次改动的守卫，于是补了真正可测的纯函数 `resolveOpeningInstruction`

只记元信息，这两个既有设计会让看似相关的测试完全失去守卫作用。

## 修复深度审查报告 C1（P0）：Agent 被要求复述它没有的题干（ADR-053）

### 用户复核后的表述更正

不是「必然幻觉」，而是 **prompt 要求模型生成它上下文里没有的数据 → 无法可靠复述真实题干 →
存在不必要的重述/幻觉风险**。根因是**职责冲突**，不是模型缺陷——这一点直接决定修复方向。

### 方案：改 prompt，不给 getQuestion 加题干

补 `question`/`options` 会让 Agent 在**选题阶段**拿到 `answer`/`explanation` 等它不需要的数据，
还扩大注入面。用户明确否决了这条路。

### 关键发现：要改的是 5 处措辞，不是报告点的 2 处

1. `prompt.ts` §你的职责 1；2. §呈现方式（整节替换为 §题目呈现（职责边界））；
3. §工具调用铁律 1；4. 开场指令步骤 2 + 结尾；
5. `tools.ts`：`getQuestion` 的 **description** 与**结果正文**（`请呈现给用户`）、`searchQuestions` 的 `nextStep`。

**第 5 项最关键**：那句「请呈现给用户」紧跟在工具结果之后，是触发编题干最直接的指令——
只改 system prompt 会被它覆盖掉。但改的只是**措辞**，`details` 仍严格是 `{id, format, matchedBy}`，
有测试断言 `Object.keys(details)` 守着。

**教训**：这类「prompt 与 UI 职责冲突」的问题，凡是有文字能触发模型动作的地方都要排查一遍——
工具 description、工具结果正文、nextStep 提示，都算 prompt。

### 与 ADR-052 的边界（重要，别搞混）

052 说「不写模型无需执行的说明」，但 053 在禁令后**保留了一句理由**（「题目正文不在你的上下文里」）。
判断标准：**理由是否服务于一条模型需主动执行的规则**——
服务于「无需执行」的一律不写；服务于「必须执行且反直觉」的禁令可留一句短理由
（模型天然想复述题目，不说「你没有这段数据」压不住）。已写进 `prompt.ts` 头注释。

### 保留弹性

不写「绝对禁止提及题目内容」——开放题反馈里引用关键概念有价值（「你解释了 KV Cache 的作用，但…」）。
禁令只针对「重新生成/完整复述」，测试里同时断言「含『可以简短引用题目的关键概念』」且「不含『绝对禁止』」。
