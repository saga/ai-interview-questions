## 修复 P0 #7：getQuestion topic 兜底重复出题（ADR-048）

用户指定只修这一项。已完成，代码改动落在 `src/agent/tools.ts` + `src/agent/tools.test.ts`。

### 改了什么

1. 新增 `isDelivered(session, id)` = 已作答 ∪ 已评分 ∪ 正是当前题，作为「是否已交付」单一出处。
   **关键细节**：`evaluations[id]` 用 `in` 而非真值判断——`null`（未作答/评估失败）也算已交付，与 `countEvaluated` 同口径，否则「答不上来的题」会被反复追问。
2. topic 兜底 `unasked[0] ?? byTopic[0]` → `byTopic.find(x => !isDelivered(...))`，不存在时宁可不出题。
3. 主题耗尽返回新错误码 `topic_exhausted` + 回带全题库中未交付的题号，**不擅自换主题**（换主题是 Agent 的选题决策，工具不越权）。
4. `validIdPool` → `deliverableIds`：not_found 自纠正回带的题号同样过滤已交付项（此前会把正在答的当前题也列进建议，等于诱导重复选题），并剔除已不在题库的陈旧 id。
5. 全题库考察完 → 明确提示 `finishInterview`。
6. 同步 `getQuestion` 的 tool description（该描述即 LLM 可见提示，必须与代码一致）。

## 任务三：`getCoverageGaps` 重定义为 coverage-based 事实查询（用户指定设计，非报告建议）

用户给了明确设计约束，逐条落地：**不删除工具、不做成推荐系统、`recommendWeakTopics()` 不参与、它应该是事实查询工具、不需要测复杂 ranking**。改动范围：`src/agent/tools.ts` + `src/domain/learner.ts` + 两个测试文件。

### 实现

- `domain/learner.ts` 新增 `CoverageGapReason = 'uncovered' | 'prerequisite'`、`CoverageGap {topic, reason, prerequisites?}`、`findCoverageGaps(topicRefs, profile, {threshold?, limit?})`、`describeCoverageGap(gap, profile)`。
- 语义正交：`getUserWeaknesses` = **mastery-based**（已练但薄弱）；`getCoverageGaps` = **coverage-based**（还没练到）。判据：**已练但未掌握、前置完备的 topic 不算覆盖缺口**。
- 缺口只两类；前置缺口排序在前（基础没打就练上层是无效投入），同档内 `topoRankOf` + 字典序保证稳定可测。
- 复用既有能力：`collectTopicRefs` / `prerequisiteClosure` / `isAttempted` / `isMastered` / `WEAK_AVG`。**没有发明 `hasEvidence`**——"练过没有"用既有的 `TopicStats.attempts`。
- 只统计题库中也存在的前置：用户无从练习的前置不是可闭合缺口（那是题库生产问题，归 `domain/coverage.ts` 视角）。
- `recommendWeakTopics()` 完全移出该工具；description 写明分工（description 即 LLM 可见提示）；补 `session.log` 条目。

### 偏离用户方案的一处（已在 ADR-049 记录理由）

用户建议放 `src/domain/coverage.ts`，我放在了 **`src/domain/learner.ts`**。理由：`domain/coverage.ts` 是 ADR-032「两速分离」下**题库生产侧**的 topic×angle 矩阵，不感知 `LearnerProfile`、运行时不加载；而本函数依赖 `isAttempted`/`isMastered`/`WEAK_AVG`/`prerequisiteClosure`，全在 `learner.ts`。放进 `coverage.ts` 会让它反向依赖 learner 概念。

### 反向验证（两轮，都有效）

1. 还原旧的 `recommendWeakTopics` 实现 → **4 例工具测试全失败**。
2. 破坏 `findCoverageGaps`（去掉前置优先排序 + 去掉 `isAttempted` 守卫）→ **3 例 domain 测试失败**。

第一次反向验证**失败了**：用 python `str.replace` 注入破坏代码时字符串没匹配上（目标是多行格式），测试全绿但没有真正改动文件。教训：**注入破坏性改动后必须 `diff` 确认真的改到了**，否则会得出"测试没覆盖"的错误结论。

### 一个自测断言写错

`describeCoverageGap` 的用例我最初断言 `WEAK`（`attempts: 3`）的前置缺口描述为「未练习，前置…」，但 `isAttempted` 为 true 时应该只说「前置…尚未掌握」。**实现是对的，测试写错了**，已改为覆盖三个分支：未练习 / 前置未掌握 / 未练习+前置未掌握。
