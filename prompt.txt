
先分析文章内容，识别其中值得考察的核心知识点（Concept / Subtopic），再从这些知识点中选择最有面试价值的部分，生成 4～10 道选择题（单选或多选，多选优先，但题型应根据知识点和考察角度自然选择）。

不要平均覆盖文章，也不要简单按照文章段落顺序出题。

优先选择：
1. 重要性高的知识点
2. 能区分候选人理解深度的知识点
3. 容易产生误解或存在典型错误认知的知识点
4. 能考察机制、应用、工程判断或 trade-off 的知识点

### 知识点与考察角度

围绕重要 Concept / Subtopic，从不同角度进行考察，而不是对同一个知识点重复换一种说法。

优先考虑以下考察角度：

- fundamental：基本概念、核心原理
- mechanism：内部机制、工作过程、因果关系
- comparison：不同方法、架构或方案之间的区别
- tradeoff：设计取舍、优缺点、适用条件
- scenario：真实工程场景中的应用和判断
- debugging：根据现象定位问题、分析错误原因
- design：根据需求设计或选择技术方案
- calculation：涉及计算、复杂度、资源或数量关系时进行定量判断

不要求每个知识点覆盖所有角度，也不要为了凑齐角度而生成低价值问题。

对于重要 Concept，如果多个角度都具有较高面试价值，应优先选择不同角度进行覆盖，从而形成对该 Concept 的多维考察。

避免连续生成本质相同的问题。例如，如果已经通过 mechanism 考察了 self-attention 的工作原理，就不要仅仅换一种措辞再次考察相同内容；应优先考虑 comparison、tradeoff、scenario 或 debugging 等不同角度。

### 题目必须 self-contained

每道题必须是自包含的。

假设考生完全看不到原文章，也没有阅读过原题，仅通过当前题目的题干和选项，就应该能够：

1. 理解题目所描述的技术背景和问题；
2. 理解必要的场景、架构或设计约束；
3. 根据自己的知识进行推理并作答。

如果某个知识点依赖文章中特定的技术背景、架构、实验结果、设计决策或上下文才能形成有价值的问题，应将回答该问题所必需的最小 context 提炼并写入题干。

不要使用依赖原文章的表达，例如：

- “文中提到……”
- “根据本文……”
- “上述方法……”
- “该方案……”
- “作者认为……”
- “前文所述……”

除非相关对象已经在当前题干中被明确描述。

不要把整段文章搬进题干。

只加入理解和作答所必需的最小 context。题干中的 context 应服务于问题，而不是变成文章摘要。

### 题目应考察理解，而不是文章记忆

题目应主要考察：

- 对概念和机制的理解
- 对因果关系的理解
- 对不同方案的比较
- 对工程 trade-off 的判断
- 在具体场景中的应用
- 对错误实现或错误认知的识别
- 必要时进行定量或复杂度分析

避免考察：

- 文章中的原句记忆
- 单纯记忆文章中的数字
- 作者使用的特定措辞
- “文章列出了哪几个……”这类低价值阅读理解题

除非某个数字、事实或结论本身就是该知识点不可分割的重要组成部分。

### 题目质量与变体要求

同一个 Concept 可以生成多道题，但每道题必须具有明显不同的考察意图。

例如，对于 Transformer，不要只生成：

- Transformer 是什么？
- Transformer 的核心是什么？
- Transformer 的主要特点是什么？

而应尽可能形成不同角度的考察，例如：

- self-attention 的机制
- MHA / MQA / GQA 的比较
- KV cache 的工程 trade-off
- 长上下文场景下的性能问题
- attention 实现中的常见错误
- Transformer 架构设计取舍

题目之间应该具有互补性，而不是简单改写。

### 输出

对每道题给出：

- 题型：单选 / 多选
- Concept / Subtopic：主要考察的知识点
- Angle：fundamental / mechanism / comparison / tradeoff / scenario / debugging / design / calculation
- 题干
- 选项
- 正确答案

最终只输出 4～10 道最有面试价值的题目。

在生成完成后，对每道题进行一次检查：

1. 删除原文章后，题目是否仍然可以独立理解？
2. 是否明确考察一个核心 Concept / Subtopic？
3. 是否有明确的考察角度？
4. 是否真正测试理解、应用、判断或 trade-off，而不是文章记忆？
5. 如果同一个 Concept 出现多次，这些题是否具有不同的考察角度？
6. 是否存在更有区分度、更有面试价值的题目可以替代当前题目？
