# Unslop：中文技术内容表达校正

## 目标与边界

让内容读起来像一位真正理解主题的工程师在解释问题：直接、具体、准确，句子自然，不靠套话、营销词和固定模板撑篇幅。

本 skill 只处理**表达质量**，不代替事实核验、课程设计或题目质量规范：

- 题目知识边界、答案确定性、选项设计、难度和诊断价值，以 `docs/question-content-spec.md` 为准。
- Snowflake / SAP 等产品行为，以对应官方文档和课程来源为准。
- 本 skill 不允许为了流畅改动技术结论、答案、约束条件或来源信息。

默认采取**最小修改**：先读完整内容，定位确实影响理解的句段，只修改这些位置。没有明确问题就保留原文，不为了体现“做过润色”而改写。

## 何时应用

以下内容在定稿前必须经过本 skill 的表达审查：

- 学习文章、课程教材、知识点说明、案例分析和技术文档；
- 新生成或修改的题干、选择项、开放题参考答案、解析和 misconceptions；
- 由文章、课程、官方文档或题库蓝图生成的内容。

调用方式：

- **生成流程**：内容初稿完成后，执行一次 `review-and-fix`，修复确认存在的问题，再做事实与结构复核。
- **仅审查**：用户要求“只检查、不修改”时使用 `audit-only`，只报告问题，不动原文。
- **定点修改**：用户指定某处时，只修改指定范围及其直接受影响的句子。

不要把整篇文章送入无差别“人性化改写”。不得静默改变用户已认可的表达或无关段落。

## 审查步骤

1. **完整阅读**：包括标题、正文、表格、图注、示例、引用和结尾。不要只根据孤立句子或关键词判断。
2. **找具体缺陷**：指出哪一段在重复、遮蔽结论、夸大、含糊、空转或套用固定结构。说明它影响了什么。
3. **结合上下文判断**：术语、否定、限定条件、比较句和固定教学结构可能是准确表达，不能只因形式相似就删除。
4. **最小修复**：优先删掉无信息量的开头、重复解释和空泛结尾；需要改写时保留原句要表达的事实和范围。
5. **重新核对**：逐项检查事实、条件、数字、来源、代码、逻辑关系和知识边界有没有变化。
6. **无问题则不改**：保持原文，不制造人为的句长变化或所谓“人类口吻”。

## 常见表达问题

具体中文例子见 [references/chinese-patterns.md](references/chinese-patterns.md)。重点关注以下类型，而不是把词表当禁用词：

- **铺垫空转**：开头连续解释“为什么重要”，却迟迟不说明主题、机制或结论。
- **意义膨胀**：使用“具有重要意义”“发挥关键作用”“全面赋能”“引领变革”等词，却没有给出具体作用对象、机制或证据。
- **业务套话**：用“抓手、底座、生态、闭环、全方位、深度融合”等词代替可验证的动作、接口、状态和结果。
- **翻译腔**：英文句式逐字搬进中文，堆叠“基于……维度”“在……层面”“通过……来实现”等结构。
- **模板化转折**：反复用“不是……而是……”“不仅……更……”“从……到……”制造对比，但两侧并无必要的逻辑关系。
- **机械节奏**：每段都按“首先、其次、此外、最后”开头；每节固定三点；句子长度和段落结构高度重复。
- **空泛标题和结尾**：标题只写“核心价值、重要意义、未来展望”；结尾只是重复全文或给出没有信息的展望。
- **无来源的权威语气**：“研究表明、业界普遍认为、实践证明”没有明确来源或证据。
- **自我旁白**：“下面我们深入探讨”“值得注意的是”“不难发现”“综上所述”等话语没有带来新的信息。
- **虚构具体性**：为了显得真实而编造客户经历、性能数字、项目经验、引用或作者亲历。

词语本身不构成缺陷。是否修改取决于它在当前句子里是否承担实际语义。

## 学习文章的表达要求

- 以要解释的机制、问题或工程判断切入；不要用泛泛的行业背景凑开头。
- 标题说明这一节具体讲什么，不用宣传式标题或抽象口号。
- 让每段承担明确任务：解释机制、给出条件、展示例子、比较取舍或说明验证方法。相邻段落不要换一种说法重复同一结论。
- 文章应给出实际工程边界：适用条件、限制、失败模式、恢复方式、观测指标和验收证据。没有来源或证据时明确标为推演/教学场景。
- 使用表格、列表、SQL、代码块和 Mermaid 图，只在它们比纯文字更易理解时使用；不要为了“版式丰富”而堆组件。
- 保留必要的学习目标、步骤、检查题和章节层次。教学结构本身不是 AI 痕迹，不要把教材改成没有层次的短文。
- 结论应落到具体判断或行动条件，不要再写一段摘要式口号。
- 不能为了“像人写的”故意加入口语、段子、情绪、第一人称经验或主观评价。

## 题目与解析的表达要求

题目语句自然，先保证**可判定和无歧义**，再考虑简洁：

- 题干只保留作答所需的场景、目标、约束和证据。角色背景、行业故事和数字必须对判断有作用。
- 不要批量复用同一个题干开头或固定情境模板。题目相似时，应先改变真实考察场景或认知任务，而不是机械替换公司、系统和人名。
- “以下哪些说法正确”“最合适的做法是什么”“在实际工作中应如何处理”并非禁用句式；若它们没有给出判断条件、答案边界或真实决策点，就需要补充场景或重写。
- 选择项应简洁、同一认知层级、彼此独立。不要把正确项写成更完整的教程段落，也不要给错误项塞无关文字凑长度。
- 干扰项用真实误解、条件错配、范围偏差或因果判断错误；不要靠荒谬、夸张或语气明显的选项凑数。
- 解析直接说明判断依据、关键前提和错误选项的边界，不要只写“正确答案是 A、B”或重复题干。
- `misconceptions` 描述考生真实可能出现的误解，不要写成泛泛的“缺乏理解”“考虑不全面”。
- 保留题目规范要求的必要术语。产品名和 API 名称是考点所需时不应刻意删除。

题目语义与数据结构仍由 `docs/question-content-spec.md` 和题库 schema 决定。本 skill 不得改变答案索引、答案集合、angle、difficulty、Knowledge ID、source metadata 或题目身份。

## 必须保护的内容

任何修改都不得悄悄损坏以下信息：

- 数字、单位、时间、比例、版本、产品名、API / SQL / 配置名、URL、文件路径和代码；
- 来源归属、引文、案例性质、事实与推断的区别；
- “仅、必须、可以、不得、通常、可能、至少、至多”等范围和强度；
- 否定、例外、前提、因果、条件、角色责任、权限边界与时序；
- 题干与答案的对应关系、选项正确性、评分依据和 misconceptions；
- 原文明确承认的不确定性。

不得新增未经来源支持的数字、客户案例、性能结论、权威观点或个人经验。不得把“可能”润色成“必然”，把“部分支持”改成“全面支持”，也不得删除安全、法律、运维和数据治理中的必要限定。

引文、代码块、SQL、JSON、命令、产品界面文本和用于说明错误写法的示例应按原样保护。除非用户明确要求修改这些内容，不要把它们当作待润色正文。

## 不能采用的做法

- 不使用英文版 UNSLOP 的扫描脚本或英文禁词表判断中文文本。中文词语高度依赖上下文，机械匹配会误伤技术术语和必要表达。
- 不设置“命中某词必须删除”的硬规则；词表只是审查提示。
- 不以句长方差、段落数量、三点列表数量或某个所谓 AI 分数作为质量结论。
- 不把所有对比句、被动句、列表、表格、术语重复、专业限定语都当成问题。
- 不将技术教材改成营销文案、社交媒体口吻或刻意不完整的短句。
- 不在没有文本证据时断言作者或内容“由 AI 生成”。本 skill 判断的是表达问题，不判断作者身份。

## 完成检查

定稿前逐项确认：

- 开头是否尽快进入主题，结尾是否提供了真实结论；
- 每段是否增加了新信息，标题是否准确描述内容；
- 是否有可以直接删除而不损失含义的句子；
- 是否出现机械重复的转折词、段落结构或固定三段式；
- 抽象词是否落实到具体机制、动作、指标或证据；
- 技术术语是否准确，中文表达是否自然；
- 所有事实、引用、数字、限定条件和逻辑关系是否保持；
- 题目是否仍然符合内容规范，答案和评分语义是否完全不变。

生成流程的最终交付不必附带“已去 AI 味”的自我评价。只需输出修订后的内容；只有审计请求才列问题清单。

## 来源与改编说明

本 skill 参考 [theclaymethod/unslop](https://github.com/theclaymethod/unslop) 的核心思想：先完整阅读，再按上下文确认缺陷；编辑最小范围；区分明确问题与风格判断；保护事实、引文和技术语义；无真实缺陷时不改写。

这里针对中文技术学习内容重新编写规则，没有复制其英文扫描器、禁词表、实现代码或评分系统。中文表达示例见 [references/chinese-patterns.md](references/chinese-patterns.md)。
