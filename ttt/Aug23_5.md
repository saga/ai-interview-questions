

# 最好把「题目」和「回答形态」彻底分开

你的场景里实际上存在三个东西：

```text
Question
   │
   ├── Content
   │     ├── question
   │     ├── category
   │     ├── topic
   │     └── difficulty
   │
   ├── Presentation
   │     └── choice / open
   │
   └── Evaluation
         ├── exact answer
         └── LLM evaluation
```

所以我更推荐：

```json
{
  "id": "cv-03",

  "content": {
    "question": "简述目标检测中 One-Stage（如 YOLO）与 Two-Stage（如 Faster R-CNN）方法的核心区别与各自优劣。"
  },

  "metadata": {
    "category": "computer-vision",
    "topic": "object-detection",
    "tags": ["detection", "yolo", "faster-rcnn"],
    "difficulty": "hard"
  },

  "formats": {
    "open": {
      "enabled": true,
      "referenceAnswer": "Two-Stage 先生成候选区域……",
      "evaluation": {
        "explanation": "考察候选区域两阶段 vs 端到端单阶段，以及精度/速度权衡。",
        "reference": {
          "concept": "Two-Stage 先提候选区再分类，精度高速度慢；One-Stage 端到端，速度快。"
        }
      }
    },

    "choice": {
      "enabled": true,
      "type": "single",
      "options": [
        "One-Stage 需要先生成候选区域",
        "Two-Stage 通常速度更快",
        "YOLO 属于 One-Stage",
        "Faster R-CNN 属于 One-Stage"
      ],
      "answer": [2]
    }
  }
}
```

这样就非常自然地支持：

```text
                    Question
                       │
          ┌────────────┴────────────┐
          ▼                         ▼
      Choice                      Open
          │                         │
      自动判分                    LLM评分
          │                         │
          └────────────┬────────────┘
                       ▼
                  Evaluation
```

---

# 这样你之前的 ADR-024 就会变得非常简单

你之前说：

> 同一道题在 选择题 ⇄ 开放题之间换形态

如果采用上面的结构，实际上**不需要转换题目本身**。

只需要：

```ts
question.formats.choice
question.formats.open
```

然后 UI 决定：

```ts
const format = sessionQuestion.format
```

例如：

```ts
format === "choice"
```

显示：

```text
○ A
○ B
○ C
○ D
```

而：

```ts
format === "open"
```

显示：

```text
┌─────────────────────┐
│                     │
│   输入你的答案...    │
│                     │
└─────────────────────┘
```

**同一个 Question ID 不变。**

### 我现在最推荐的版本

```json
{
  "id": "cv-03",
  "category": "computer-vision",
  "topic": "object-detection",
  "tags": ["detection", "yolo", "faster-rcnn"],
  "difficulty": "hard",

  "question": "简述目标检测中 One-Stage（如 YOLO）与 Two-Stage（如 Faster R-CNN）方法的核心区别与各自优劣。",

  "formats": {
    "open": {
      "referenceAnswer": "Two-Stage 先生成候选区域……",
      "explanation": "考察候选区域两阶段 vs 端到端单阶段，以及精度/速度权衡。"
    },

    "choice": {
      "type": "single",
      "options": [
        "One-Stage 需要先生成候选区域",
        "Two-Stage 通常速度更快",
        "YOLO 属于 One-Stage",
        "Faster R-CNN 属于 One-Stage"
      ],
      "answer": [2]
    }
  }
}
```

然后**默认 format 单独放在 session/question instance 里**：

```json
{
  "questionId": "cv-03",
  "format": "open"
}
```

这样非常关键。

因为：

> **Question 是题库里的知识对象；SessionQuestion 才决定这次面试怎么问。**

于是同一道题可以：

```text
第一次：
cv-03 → choice

第二次：
cv-03 → open

第三次：
cv-03 → open
      ↓
      follow-up
```

而题库完全不用修改。

### 最终我会把你的模型定成：

```text
Question
├── id
├── metadata
├── question
└── formats
    ├── choice
    └── open

SessionQuestion
├── questionId
├── format
└── answer
```

这已经足够支持你前面讨论的 **选择题 / 开放题动态转换 + LLM 评分 + 个性化面试**，同时不会把 JSON schema 做得过重。
